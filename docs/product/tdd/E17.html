E17: Model integration and tool-use optimization

Technical design document brief · Full hackathon scope · Existing weights only

Owner C. Stage S4. Dependencies E10, E12, E13. Requirements R23, R30.

Use the existing medically adapted HuatuoGPT-3 candidate. No additional SFT, LoRA, QLoRA, preference optimization or RL training. This is Joaquin's clarified scope.

Decisions for the TDD

Pin model, tokenizer, license, chat template, thinking mode, quantization and runtime. Verify tool-call and structured-output compatibility. Specify the prompt/context builder, stage-specific tools, retrieval configuration, verifier, loop budgets, memory scheduling and rollback. Compare configurations on development cases with fixed weights; keep final evaluation sealed.

Work packages

E17-01: Freeze original model and runtime integration

Acceptance: Pinned model, tokenizer, thinking mode and tool template pass parsing and memory probes.

E17-02: Optimize tool use on development cases

Acceptance: Compare staged tools, descriptions, context, retrieval and verification with fixed weights; no holdout leakage.

E17-03: Promote the evaluated deployment configuration

Acceptance: Exact quantized artifact and prompt/tool/corpus versions tested; regression blocks promotion; rollback manifest exists.

Required handoff

Configuration manifest, integration examples, experiment matrix, failure handling, cancellation, performance measurements and meaningful acceptance tests. Cite actual runs before claiming improvement. Read the shared contracts and LLM architecture before implementation.
