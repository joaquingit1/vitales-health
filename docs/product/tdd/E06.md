## Decisions the TDD must settle

Decide POS implementation, torso method, pairing and worker scheduling. Record alternatives, the selected design, evidence, failure modes and migration/rollback impact. This is a design brief, not an assertion that the technical design is complete.

## Required work and acceptance

### E06-01: Implement independent pulse and respiration pipelines

Acceptance: Pulse can pass while breathing fails; no clipped-boundary reassurance.

### E06-02: Implement station pairing and best-view selection

Acceptance: Unpaired image discarded; selected source and disagreement retained.

### E06-03: Evaluate quality and optional identity experiment

Acceptance: Held-out error, rejection and coverage reported; optional face matching separated.

## TDD completion checklist

Specify API payloads and errors; state transitions and invariants; persistence/index choices; authorization and consent checks; unit/time/provenance handling; concurrency, idempotency and cancellation; resource limits and degradation; observability without private-content leakage; fixture IDs and acceptance evidence; dependencies and integration examples. Include a sequence diagram for the principal success path and a failure path. Name unresolved clinical or equipment assumptions explicitly.

## Handoff to implementation

Produce the technical design document, concrete contract examples, implementation task breakdown and meaningful tests. Use the frozen shared contracts; propose changes through an explicit decision record. Mark evidence as planned until tests actually run.
