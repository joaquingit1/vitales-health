## Decisions the TDD must settle

Select physical board, epoch units, storage and validated algorithm applicability. Record alternatives, the selected design, evidence, failure modes and migration/rollback impact. This is a design brief, not an assertion that the technical design is complete.

## Required work and acceptance

### E08-01: Specify firmware buffering and epoch synchronization

Acceptance: Offline epochs sync once with gaps and clock offsets visible.

### E08-02: Implement sleep scoring and correction

Acceptance: Nonwear not sleep; scoring version and user correction retained separately.

### E08-03: Demonstrate physical or replay acquisition honestly

Acceptance: Source mode visible; n=1 diary comparison not presented as validation.

## TDD completion checklist

Specify API payloads and errors; state transitions and invariants; persistence/index choices; authorization and consent checks; unit/time/provenance handling; concurrency, idempotency and cancellation; resource limits and degradation; observability without private-content leakage; fixture IDs and acceptance evidence; dependencies and integration examples. Include a sequence diagram for the principal success path and a failure path. Name unresolved clinical or equipment assumptions explicitly.

Produce the technical design document, concrete contract examples, implementation task breakdown and meaningful tests.
