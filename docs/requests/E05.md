## R-E05-1: Publish one measurement seam contract

- Target: coordinator, SYSTEM owner, E05, E11, E12, E13, E15, E23, E27 and E28.
- Exact proposal: consolidate the existing E11/E12/E15/E27/E28 measurement requests into SYSTEM section 8.1, with
  E05 as sole request/attempt/gap writer. Use canonical `KitGate` from SYSTEM 4.2, with E27's method
  `check(uow: UnitOfWork, *, capability_code: str, environment_id: EnvironmentId,
  condition_ids: Sequence[str]) -> GateOutcome`. Preserve E27's GateOutcome fields (KitCheck, capability words,
  condition/plan rows in request order); make its release an explicit caller pin. Normalize KitCapabilitiesPort to
  `capabilities(view: UnitOfWork | ReadSnapshot, environment_id: EnvironmentId,
  release: ReleaseHandle) -> tuple[KitCapability, ...]`, retaining E27 3.1's exact KitCapability fields.
  CapabilityQueries.get uses that same bound view/pin and code, returning the operational Capability fact or None,
  with per-method readiness/actual device references separate from patient-specific eligibility. It never calls
  RequestGatePort, preventing E11-to-E05-to-E11 recursion. RequestGatePort.check retains E11's subject/operator
  arguments and gains explicit release/method selection and the already-computed KitCheck; publish its complete
  CapabilityFact, RequestContext and GateResult DTOs centrally. Gate order is access/binding, references, kit,
  context, operator, method/device, consent. Missing consent waits unaccepted; mid-acquisition revocation fences use.
  This resolves E11 3.7's device-before-operator order and its consent-waits versus consent-unavailable contradiction
  against E27 4.5. Current environment/operator/consent/readiness must remain checked under pinned content.
  Snapshot/pin-bind E28's existing GapPlanPort.plan_for and E27's InstrumentReadinessPort; unknown readiness is
  explicit unavailable, never all-packed-usable. E28's eligibility continues to use SYSTEM 8.2.
  Propose MeasurementProposalPort.create(uow, subject_person_id, episode_id, capability_code, reason,
  decision_affected, body_region, condition_ids, idempotency_key) -> ProposalOutcome and
  GapProposalPort.record(uow: UnitOfWork, episode_id: str, capability_or_fact: str, consequence: str) -> str.
  These are E05 proposals, not existing E12 signatures; settle pure typed DTOs with R-E12-7/R-E12-11.
  Match E12 4.3: effects join E13's apply UOW through E05 owner commands, with SessionContext/current scope
  explicit in the binding; no provider commit. Require nonempty
  decision_affected despite its nullable proposal type, preserve source/pathway references from the controller and
  reject model-supplied subject/operator authority. E12's speculative phase cannot write; cancelled/stale caller UOW
  rolls back every effect. E05 independently checks code/source/subject/episode state, including E15's explicit
  reopen rule before new work on a resolved episode.
  Add bounded authorized reads for the existing consumers: MeasurementFacts.request_states, GapFacts.for_episode,
  CapabilityFactsPort.capabilities, ObservationFactsPort.attempts_not_usable and ProvenanceStreamsPort.person_streams.
  Every read takes caller view, SessionContext, explicit patient/mission/origin where personal, limit and stable
  cursor; outputs use generated enums and Quantity, not untyped objects or bare values. E01 keeps ObservationReader.
  Adopt E15's requested internal MeasurementRequestChanged payload: request_id, nullable episode_id, patient_id,
  origin_mode, state, optional attempt with attempt_id/outcome/reason_code, at; add revision and release_id for
  deduplication/pin identity. CapabilityGapChanged carries gap_id, episode_id, state, at, revision and release_id.
  Both use SYSTEM 5.7 within the producer UOW; no new public Event enum. E13 continuations consume terminal usable
  outcomes, never the accepted permission state as if it were a result. Final pure DTO declarations and projection
  ownership are published by the coordinator before coding; the older conn/Session/ReleasePins aliases are retired.
- Reason: SYSTEM defines owners but not these methods/DTOs. E27 calls its gate KitGatePort, E11 uses another signature,
  E12 leaves effect/read signatures unbound, and E15/E13 need atomic invalidation events absent from SYSTEM. A fake cannot settle
  these disagreements. E06/E07/E08/E09/E14/E30 designs were absent when E05 was written, so their provider handoffs

- Interim: use exact SYSTEM kernel APIs and the contracted public measurement_request.changed outbox for eventual
  views only. No consumer may claim atomic episode revision/assessment invalidation from that eventual path.
  Unsupported cross-module bindings, source/episode facts or unknown gate facts leave acquisition off. Keep R06/R07/R08,
  V11/V17/V18/V25/V78, kit/context/operator/consent/source/quality checks, open pins, D1, and no fabricated result.
  Direct E01/E02 manual recording and cached help remain independent. Integration acceptance stays open.

## R-E05-2: Trusted acquisition, shared dispatch and atomic manual linkage

- Target: coordinator, E01, E02, E05, E06, E07, E08, E09 and E30; consolidate R-E01-17/25 and R-E02-8.
- Exact proposal: publish the E05 assignment proof required by E02 3.4 in SYSTEM 8.6. Proposed
  `MeasurementAssignmentPort.attest(uow: UnitOfWork, session: SessionContext, *, request_id: str,
  acquisition_id: str, generation: int) -> AcquisitionBinding`. Binding fields are request_id, request_revision,
  acquisition_id, generation, authenticated adapter_id, allowed device_ids/methods/codes, patient_id, operator_id,
  mission_id, origin_mode, release_id, accepted_at, started_at, consent/action-scope reference and terminal state.
  The returned proof comes from persisted assignments, never a caller boolean. Validate it at both E05 ingest and
  E01 append. Normalize physical times using SYSTEM TimeInput/ClockSegments; every sequence has proven segment
  mapping. The trusted producer proof in R-E01-17 also binds sample identity, actual method/device and quality rule
  hash/result to that acquisition. Do not accept quality_notes or Observation.context as proof.
  Extend AttemptCreate through the approved effective contract with acquisition_id and generation, and structured
  producer-evidence reference; retain existing sequence/outcome/observations. The hub reserves monotonically
  increasing per-request sequences at acquisition start and persists them across adapter restart. Same sequence and
  identical canonical payload is the same attempt; changed payload is a conflict even under another HTTP key.
  Publish `MeasurementCommands.validate_record_link(uow, session, *, request_id, observation_input, producer_proof)`
  and `MeasurementCommands.link_record(uow, *, validated_link, observation_ref) -> None` as part of the consolidated
  E01 records interface, with pure typed DTOs using Quantity. E01's recordObservation calls both inside its own UOW;
  E05 recordAttempt calls E01 append in the outer E05 UOW. No nested transactions or generic cross-module SQL.
  Self/verified-officer unlinked manual capture never needs the assignment port. E09 imported_report supplies its
  confirmed source/span/time proof; E30 supplies its explicit manual operator and sample, retaining Q8 behavior.
  SYSTEM 5.8 already classifies every measurement mutation through CommandPolicy and supplies AcceptedReceipt;
  apply it unchanged, including private HMAC and current replay visibility, without a new classification request.
  SYSTEM 5.10.1 already supplies TaskQueue/TaskHandler, leases, generations, recovery and cancellation. Register
  acquisition handlers with public_kind null. Settle only the additional physical start/cancel/status receipt binding
  with the device owners. Proposed worker
  transport operations are start(binding, reserved_sequence), cancel(acquisition_id, generation), and
  status(acquisition_id, generation), with authenticated bounded replies distinguishing started, stopped,
  cannot_stop and unknown. One acquisition identity has at most one physical start; duplicate dispatch returns its
  receipt. A device that cannot establish an external receipt after restart never receives a blind new start.
  Coordinator/worker owners must settle exact DTOs and transport schemas, plus the device/band worker descriptor
  names and caps for call timeout, health, retries, restart window and backoff under SYSTEM 3/5.11. No device/band
  worker may start before these descriptors are registered. No public Job kind is invented. Separate
  task completion from evidence ingestion: late/cancelled task completion returns false under SYSTEM 5.10.1, while
  an authenticated real reading is retained through recordAttempt's quarantined evidence path. Worker/staged-result
  disposal must not erase that input before its durable capture acknowledgment. Neither TaskHandler.execute nor
  discard writes clinical state; the trusted producer submits retained evidence through the hub boundary. An unknown
  physical receipt remains reconciliation pending and cannot cause task retry to repeat the measurement blindly.
- Reason: the current AttemptCreate has no acquisition generation or trusted quality proof. E01/E02 already block
  unsafe patient ingestion. The shared task runner now exists, but its late-result discard/retry contract needs an
  explicit physical-acquisition binding that preserves real input. Inventing an E05 queue would duplicate shared
  transaction/recovery mechanisms. Without atomic manual linkage a
  crash can leave an accepted record and an incomplete request, or vice versa.
- Interim: patient-adapter acquisition, automatic dispatch and request-linked writes stay off until their shared
  contracts exist. Preserve R06/R07/R08/R25, V08/V09/V13/V16/V35, accepted-operator/subject/method/origin/quality/unit
  checks, append-only evidence, D13 and storage-error propagation. Direct validated E01 manual entry stays available;
  no unsupported method is accepted. Unknown post-crash physical state is visible reconciliation, never success.

## R-E05-3: Retry, unavailable and late-result review transitions

- Target: coordinator and product/API owners with E05/E01/E02.
- Exact proposal: clarify CONTRACTS 4's distinction between a failed attempt and a failed request. A failed/rejected
  attempt with no usable result returns in_progress to accepted, retaining operator acceptance, so a person may
  explicitly start a new attempt under fresh gates. Infrastructure termination may end failed; failed request stays
  terminal. Add MeasurementRequestAction action `unavailable` with required configured reason, authorized for the
  subject or current accepted operator; create gap only for an actual capability/operator/context limitation, never
  preference decline. Add a closed acquisition-status projection distinguishing start_pending, acquiring,
  stop_pending, stopped, cannot_stop, unknown and late_review_required, with generation and reference-only reason.
  Cancellation commits before the physical stop call; all later arrivals remain cancelled and quarantined.
  Add an explicit late-result review command with request/attempt revision, observation IDs, accept/reject decision
  and reason. It requires current object/field grant and an authorized subject or verified officer review, preserves
  original observation/entry/receipt times and the original cancelled attempt, and reruns source/unit/quality checks.
  Acceptance creates a new attributed record linked to the original; it never changes a cancelled request to completed
  or rewrites historical quality. No assistant can review. Publish exact operationId/schema/error set centrally.
- Reason: the existing action enum is submit/accept/decline/start/cancel. It lacks PRD's Not available path and an
  explicit post-cancellation review. CONTRACTS requires retry on the same logical request but does not define the
  retry transition. Device inability to cancel cannot be represented truthfully by request.state alone.
- Interim: no invented wire action. Failure ends failed, with the reason retained; another capture requires a new
  explicit request. Cancellation is logical only until the device confirms; late readings remain quarantined and
  unusable, never erased. UI cannot claim physical cancellation without status. Keep V13, D08/D11, R06/R08, consent,
  origin, quality, unit, provenance and no result before acceptance. Same-request retry, Not available control and
  late review acceptance stay open, not reported as passed by the interim.

## R-E05-4: Minimal helper and adapter views, selection and configured words

- Target: coordinator, API owner, E02, E03, E05 and E27.
- Exact proposal: add a closed task invitation view carrying request_id, revision, configured capability label,
  operator requirement, expected duration and permitted accept/decline actions, without episode, reason, decision,
  observations or patient health details. An assigned helper may fetch it before accepting; after acceptance a closed
  task projection supplies only the consented fields needed to perform that request. Full MeasurementRequest is
  returned only with its complete object/field grant. Add method/device selection to the start action using configured

  update must be revisioned and audited; no implicit reassignment on accept.
  Change recordAttempt's response to a closed minimal receipt with request_id, acquisition_id, attempt_id, sequence,
  outcome/disposition and request revision; no clinical reason, episode, consent or other attempts. Apply the same
  projection policy to adapter idempotency replay. Use E01's durable receipt mechanism.
  E03 adds sourced ui-copy measurement words for every request/attempt state, accept/decline/start/cancel/unavailable,
  pending save, manual entry, method selection, failed quality, unknown readiness, physical cancellation outcome,
  late review and policy unavailable. Include schema/examples/loader validation and accessible labels. Existing
  configured designed_states/error_messages remain usable; no runtime literals fill absent keys.
- Reason: full required fields in MeasurementRequest cannot be truthfully redacted while retaining its schema.
  recordAttempt currently returns that full clinical resource to an adapter; helper GET exposes necessary details
  before acceptance. The closed start payload cannot choose between camera, device and manual acquisition. Existing
  copy does not define the complete workflow.
- Interim: full request reads remain owner/explicit-full-grant only; helper/adapter acquisition integrations and
  unrepresentable method selection remain off. Existing configured labels support direct manual entry; missing new
  controls are visibly unavailable, not hardcoded or mislabelled. Keep CONTRACTS 111, R07/R08, V25/V36/V75, exact
