## R-E23-22 Inspired oxygen conversion (ppO2 to PIO2)

- **Target:** Coordinator; contracts owner of `config-sensor-catalog.schema.json`, `sensor-reading.schema.json` and
  `config-unit-mapping.schema.json`.
- **Proposal:** Add a conversion `ppo2_to_pio2` to the accepted-unit `conversion` enum of the catalog, to the
  `conversion.method` enum of SensorReading and to the unit mapping, with an optional `vapor_pressure_mmhg` and its
  basis on the accepted unit, and a field on the mapping row saying which quantity the canonical unit means (the o2
  mmHg identity row means PIO2). Meanwhile the package example `sensor-catalog.example.json` should drop its o2 kPa
  `scale` row.
- **Reason:** The package example accepts kPa for o2 as a plain scale of 7.50062 into mmHg and compares the result
  with the PIO2 limits (145, 127 as a one-hour time-weighted average, 122). An oxygen cell's kPa reading is ambient
  ppO2. EV01 Table 6.2-1 (p.51) defines PIO2 = (PB - 47 mmHg) x FIO2 and EV06 separates ppO2 = PB x FiO2 from PIO2.
- **Interim:** `sensors/domain/conversion.py` implements PIO2 = ppO2 x (PB - PH2O) / PB, with PH2O taken from the
  accepted unit's configuration, needing a cabin pressure and failing closed without one. The shipped
  `config/sensor-catalog.json` accepts no kPa for o2 until the schema can name the conversion, so such a reading is
  rejected with INVALID_UNIT and never compared with a PIO2 limit.
