Technical design for epic E33. Inputs: the brief (`tdd/E33.md` in the planning package), PRD.md (section 4.13 "Stay or return
(Moon base only)", R60), USE-CASES.md (UC26), CONTRACTS.md (sections 5, 11 loader check 14, 19, 22, 27 and 28, EI11),

## 1. Scope

**Work packages.** E33-01 (return stages for lunar plans), E33-02 (the ReturnReadiness view), E33-03 (the Return and Who
decides cards and the Mars and transit wording).

**Requirements and validation.** R60 (stay or return, Moon base only), V94 (a lunar return stage viewed on `mars_surface` and
`transit`: no stage, "Return is not an option from here. The plan stays aboard."), invariant EI11, use case UC26. No demo
assertion: the brief and PRD 4.13 keep Return out of the demo until flight rule criteria exist.

**Delivered here.**

1. Module `crew_health.readiness`: a pure `compute_return_readiness` function and the `getReturnReadiness` endpoint
   (computed on read, nothing stored).
2. The RTDC verifier: a parser for the Removal to Definitive Care (RTDC) columns of a saved Clinical Findings Form's Table 4,
   used to prove every `rtdc` in `onboard-plans.json` was copied from its form and page (the `rtdc` clause of loader check 14),
   and a command that prints the values to copy.
3. The return stage content (E33-01) inside `config/onboard-plans.json`, through E28 (section 13 and request X1).
4. `ui/crew/src/features/readiness/`: `ReturnCard`, `WhoDecidesCard` and `NoReturnCard`, mounted in E28's plan detail.

**Not delivered here (and who does).**

| Item | Owner |
|---|---|
| PlanView, PlanRun, plan run actions (including `step_done` on prepare steps and `close` with `preparing_return`) | E28 |
| The `return` stage in PlanView and `no_return_text` | E28 (E33 supplies the content and the verifier) |
| The rest of loader check 14 and the configuration loader | E28 (plan rules), E01 (loader) |
| Active environment profile, environment switching, `return_option` content in environment-profiles.json | E23 |
| Deciding to return, any evaluator that sets a criterion `met` or `not_met` | Nobody in this release (CONTRACTS 27) |
| The device cache of the active plan with the hub stopped | E29 |

### 3.2 State (CONTRACTS 27)

```python
class ReadinessState(StrEnum):
    CLOSED = "closed"; OPEN = "open"; PREPARING = "preparing"; STOOD_DOWN = "stood_down"

def compute_return_readiness(
    subject: PersonRef,
    environment: ActiveEnvironment,
    runs: Sequence[RunSnapshot],         # the subject's runs opened at or after environment.activated_at
    words_for: Callable[[str | None], ReadinessWords],   # by ui-copy version; None means the active version
    now: datetime,
) -> ReturnReadiness | NotApplicable: ...
```

1. `environment.return_option is None`: return `NotApplicable` (the API answers 422 CONTEXT_INAPPLICABLE; EI11).
2. Candidates: runs whose `return_stage` is not `None` and lists `environment.environment_id`.
3. Selection, in this order: (a) the most recently opened candidate not `closed`: state `preparing` when any prepare step of
   its stage is `done` in the run, else `open`; (b) otherwise the most recently opened `closed` candidate when a prepare step
   was done: `preparing` when its `close_disposition` is `preparing_return`, `stood_down` otherwise (request X7 confirms the
   `preparing` reading); (c) otherwise `closed` with nothing listed, as in `return-readiness-closed.json`.
4. With a selected run: `criteria` are the stage's criteria, each with `status` `unknown` and `evidence_ids` `[]` (no rule
   evaluates a criterion in this release); `criteria_text` is `return_criteria_pending` while any criterion has
   `to_be_set_by` "flight rules", else `None`; `prepare` lists the stage's steps with the run's `state` (`done` or `open`),
   `by` and `at`; `decided_by` and `rtdc` are the stage's; `plan_run_id` and `plan_id` are the run's. Words come from the
   run's pinned ui-copy version.
5. Without a selected run: `plan_run_id`, `plan_id`, `criteria_text` and `rtdc` are `None`, the lists are empty, words come
   from the active ui-copy version.
6. Always: `who_decides_text` is `who_decides`; `trip_text` and `trip_source_ids` are the return option's; `environment_id`
   is the active environment; `as_of` is `now`.

A run whose `opened_at` is before `activated_at` belongs to an earlier place and is never a candidate: moving from the Moon base
to a transit vehicle ends the Return card, and returning to the base does not revive an old run.

### 3.3 The RTDC verifier (domain, pure)

```python
@dataclass(frozen=True, slots=True)
class Table4:
    page: int                            # the last "[page N]" marker before "TABLE 4."
    rows: Mapping[Literal["treated_best", "treated_worst", "untreated_best", "untreated_worst"], PctRange]
    row_tokens: Mapping[str, tuple[str, ...]]   # the raw tokens of each row, for the human check

class Table4Refusal(StrEnum):
    NO_TABLE = "no_table"; NO_PAGE = "no_page"; MISSING_ROW = "missing_row"
    NOT_NUMERIC = "not_numeric"; OUT_OF_RANGE = "out_of_range"; MIN_ABOVE_MAX = "min_above_max"

def parse_table4(form_text: str) -> Table4 | Table4Refusal: ...
def verify_rtdc(rtdc: Rtdc, form_source_id: str, form_text: str) -> list[RtdcMismatch]: ...
```

The saved form texts carry `[page N]` markers. The parser finds the line starting `TABLE 4.`, stops at `TABLE 4 KEY`,
splits rows at the lines ending `(TBC)`, `(TWC)`, `(UTBC)` and `(UTWC)`, drops trailing lines with no digit (the next row's
label is printed on its own line before its abbreviation), and reads the last four tokens of each row as RTDC min, RTDC max,
LOCL min and LOCL max (the column order printed in the table header: `RTDC Min Max`, `LOCL Min% Max%`). It refuses rather than
guesses (charter section 1, rule 4). Values are `Decimal`, never float. `verify_rtdc` reports every field that differs, the
page if it differs, and a `source_id` that is not the form.

Evidence that the rule reads the forms correctly: a prototype run over the fourteen saved forms with a Table 4 (RS07, RS10,
RS14, RS24, RS28, RS29, RS32, RS33, RS34, RS40, RS43, RS52, RS55, RS58) parsed all fourteen; RS32 gives page 5, treated best
0 to 0, treated worst 96 to 100, untreated best 0 to 100, untreated worst 100 to 100, exactly the `rtdc` of `plan_eye_injury`
and `return-readiness-tomas.json`. The first prototype failed on every form because the next row's label line ("Treated
Worst") sat at the end of the previous row; the trailing no digit rule fixed it. The other thirteen results are parser output
only: each is checked by a person against the PDF page before any stage cites it (section 8, step 3 of the content procedure).

### 4.2 Use case

| Use case | Input | Output | Errors | Idempotency |
|---|---|---|---|---|
| `GetReturnReadiness` | `subject` (optional), session | ReturnReadiness | UNAUTHORIZED_SCOPE (role, another subject without the role, unknown subject), CONTEXT_INAPPLICABLE (no active environment, or `return_option` `null`), MALFORMED_REQUEST | Read only |

Steps: resolve the subject (default the session person; I33-10); read the active environment; read `return_option` from
environment-profiles in the profile's release; if `null`, raise `ReturnNotApplicable`; ask E28 for candidates since
`activated_at` with `limit` `settings.readiness.closed_runs_limit`; for each candidate read its pinned onboard-plans document
and resolve its return stage; call `compute_return_readiness`; map to the response model.

The `subject` is resolved before the environment check, so a crew member asking about someone else gets 403 on Mars too and
learns nothing about the place from the error.

## 5. Adapters

**Storage.** None. Readiness is computed on read (CONTRACTS 27); there is no table, no migration and no rollback beyond
removing the module.

**Gateways.** `adapters/environment_gateway.py` (E23 port), `adapters/plan_runs_gateway.py` (E28 port),
`adapters/config_gateway.py` (E01), `adapters/people_gateway.py` (E02). In-process calls; no network.

**Saved form store.** `adapters/form_text_store.py` reads saved form text by `source_id` from the location SYSTEM.md fixes
(the package keeps them at `research/responder/RSxx.txt`; request X8). Reads are bounded to 2 MB per file and done at loader
time or by the CLI, never on the request path.

**CLI.** `uv run crew-health-rtdc <source_id>` prints the parsed page, the four ranges and each row's raw tokens, as JSON ready
to paste into a stage; `--check <onboard-plans.json>` runs `verify_rtdc` over every return stage and exits non-zero on any
mismatch or refusal. Script entry through request X9.

## 6. API

| operationId | Method and path | Request | Success | Errors (exactly those in openapi.yaml) | Headers |
|---|---|---|---|---|---|
| `getReturnReadiness` | `GET /v1/return-readiness` | `subject` (query, optional, `q_subject`) | 200 ReturnReadiness | 400 MALFORMED_REQUEST; 401 UNAUTHENTICATED; 403 UNAUTHORIZED_SCOPE; 422 CONTEXT_INAPPLICABLE; default INTERNAL_ERROR | `Config-Release` (the active release), `X-Correlation-Id` |

Roles (`x-roles`): `crew`, `crew_medical_officer`, `station`. `crew` may read only itself (`q_subject` description). An
unknown subject answers 403, so the endpoint does not reveal who exists (the operation has no 404; request X10 offers one).
The 422 envelope carries `current_state` `{environment_id}` and no `supported_alternative`; the client shows ui-copy
`error_messages.CONTEXT_INAPPLICABLE`, never `message`.

Station: `station_leo` has a non-null `return_option`, so the endpoint answers 200 there (`closed` with the station trip
text, since no E33 stage lists the station). This follows CONTRACTS 27 ("and the station per flight rules") over the brief's
"outside the Moon base it answers not applicable"; request X7 asks the coordinator to confirm.

Examples reproduced byte-equal by tests: `return-readiness-tomas.json` (open) and `return-readiness-closed.json` (closed), on
the SIM fixture clock `2026-11-13T12:35:00Z`.

## 7. User interface

Files under `ui/crew/src/features/readiness/`. Mounted by E28's "The plan aboard" screen in the Return slot (paper, columns 15
to 24, rows 1 to 2) and the Who decides slot (deep green, columns 15 to 24, row 3), UX-DESIGN 1.2 and 3.8.

| Component | Binds to | Shows |
|---|---|---|
| `ReturnCard.vue` | `GET /v1/return-readiness?subject=` (screen map, CONTRACTS 19); refetch on `plan_run.*` | Title `plan_stage_words.return`; the trip line (`trip_text` with its source chips from `trip_source_ids`); `criteria_text`; each criterion's `text` with its source chips; "what to prepare" as steps (`prepare[].text`, done ones with their time); the RTDC block when its words exist (X3); the mode word `plan_mode_words.prepare_return` when `state` is `preparing` |
| `WhoDecidesCard.vue` | the same response | `who_decides_text` only |
| `NoReturnCard.vue` | PlanView `no_return_text` | The sentence, verbatim, in the Return slot |
| `useReturnReadiness.ts` | the endpoint | Typed client from the generated types; 422 maps to "not applicable here" so the plan detail draws `NoReturnCard` |

Marking a prepare step done uses E28's plan run client (`POST /v1/plan-runs/{id}/actions` `step_done`, If-Match), not an E33
endpoint; prepare steps are `who` `crew_medical_officer`, so E28's authorization decides who sees the control (request X2).

**States.**

| State | What shows |
|---|---|
| Loading | Card frames, no text |
| Not applicable (Mars, transit) | `NoReturnCard` with `no_return_text`; no Who decides card |
| Closed | Title, trip line and `who_decides_text`; no criteria and no steps (the closed example) |
| Open | Criteria with `criteria_text`, the prepare steps open, Who decides |
| Preparing | As open, done steps marked with time and the mode word |
| Stood down | As open, with the prepare steps' states; no mode word (X3 asks for a `stood_down` word) |
| Readiness and PlanView name different runs | The PlanView's own return stage (criteria, prepare steps, trip) without state or step marks, until X11 lets the card ask for a specific run |
| Error | ui-copy `error_messages[code]`, never the envelope's `message` |
| Offline or hub stopped | The device cache's PlanView return stage if E29 caches it, labeled with its release version; no state; nothing else |
| LIVE, REPLAY, SIM | The fixture's origin swatch on the plan detail (E28); readiness carries no reading of its own |

**Wording.** No component composes a sentence, a verb, a recommendation, a color for the chance or an icon that ranks the
options. The RTDC numbers render only as the four ranges inside a block whose labels come from ui-copy (X3: `return_words.rtdc_title`,
`rtdc_note` "NASA's model, never a decision rule", `treated`, `untreated`, `best_case`, `worst_case`, `range` with `{min}` and
`{max}`, `prepare_heading`, `criterion_unknown`, `stood_down`). Until X3 lands the block, the heading and the stood down word are
not drawn, which hides data but never shows an unlabeled number.

**Kept out of the demo.** There is no feature flag: the demo fixture (Mara, ICL10, `plan_icl10` has no return stage) never
produces a candidate, so the card shows `closed` content only if the presenter opens a lunar plan detail. T33-17 asserts the
act scripts in `eval/` never call `getReturnReadiness`.

**Accessibility.** The cards are text; source chips are links with their source title; the step list is an ordered list; no
motion. **No content in client code.** T33-16 scans `ui/crew/src/features/readiness/` for rendered string literals (V98).

| `environment-profiles.json` | `profiles[environment_id].return_option` (`trip_text`, `source_ids`, `to_be_set_by`) | The release the active profile was activated under |
| `onboard-plans.json` | `plans[].stages[stage_id == "return"]`: `environments`, `criteria[]`, `prepare[]` (`step_id`, `text`), `decided_by`, `rtdc`; `sources[]` | The run's pin |
| `ui-copy.json` | `plan_lines.return_criteria_pending`, `plan_lines.who_decides`, `plan_lines.no_return` (via PlanView), `plan_stage_words.return`, `plan_mode_words.prepare_return`, `error_messages` | The run's pin, else active |

**Loader checks.** Loader check 14 (CONTRACTS 11) owns the stage rules. E33 provides the `rtdc` clause as `RtdcVerifier`
(request X4) and adds two content tests that run in `scripts/validate_contracts.py` and CI:

| ID | Check |
|---|---|
| C33-1 | Every return stage's `environments` is a subset of the environments whose `return_option` is not `null`, and every E33 authored stage lists exactly `["lunar_surface"]` |
| C33-2 | Every `rtdc` passes `verify_rtdc` against the saved form named by `rtdc.source_id`, and that source is a CliFF in `sources[]` |

**E33-01 content procedure.** For each plan E28 writes that covers `lunar_surface`:

1. List the saved forms it cites that have a Table 4 (`crew-health-rtdc --scan`).
2. Run `crew-health-rtdc <source_id>`; a person checks the four ranges and the page against the PDF and records the check in the
   stage's `basis` note in `sources[]`.
3. Write the stage only when a criterion can be quoted from a cited source; each criterion has `to_be_set_by` "flight rules".
   Prepare steps say what to prepare in the words of the source or "to be set by flight rules", `who` `crew_medical_officer`.
   `decided_by` is `["commander", "crew_medical_officer"]`.
4. Otherwise the plan has no return stage and the card shows `closed` there.

The first stage is `plan_eye_injury` exactly as in the example (RS30, RS32; RS32 page 5).

**A configuration edit changes behavior with no code change (T33-13).** Editing `plan_lines.who_decides` changes
`who_decides_text`; editing `return_option.trip_text` changes `trip_text`; setting `lunar_surface.return_option` to `null`
turns 200 into 422; removing the stage's criterion changes `criteria` to `[]` and `criteria_text` to `null`; a pinned run keeps
its versions while the active release changes (I33-11).

## 10. Safety, security and privacy

| ID | Hazard | Cause | Mitigation | Test |
|---|---|---|---|---|
| H1 | The screen reads as a decision to return or stay | A field, verb or color that ranks | No decision field or action; words only from configuration; no color for the chance; Who decides names people | T33-06, T33-16 |
| H2 | NASA's modeled values are mistyped | Hand copying | Parser and loader check against the saved form and page; CLI copy | T33-10, T33-11 |
| H3 | The modeled chance is read as this person's chance | An unlabeled number | The block appears only with its "NASA's model, never a decision rule" label (X3) | T33-16 |
| H4 | Return offered on Mars or in transit | Stage authored for the wrong place | EI11: loader check, C33-1, 422 | T33-01, T33-11 |
| H5 | A criterion shows as met without evidence | A future evaluator | `unknown` only, schema rule on `evidence_ids` | T33-05 |
| H6 | An old run from an earlier place revives the card | Runs from before the environment change | Only runs opened since activation | T33-04 |
| H7 | A crew member learns another's plan | Readiness names the plan | Crew sees only itself; unknown subject answers 403 | T33-12 |
| H8 | The trip time is read as certain | One figure | Trip text and source from configuration; range question to E23 and clinical review | Section 14 question 3 |

**Authorization.** Role check, then subject scope (I33-10). **Privacy.** Logs carry `subject` id, `environment_id`, state and
timings, never criteria or plan text. No journal or report data is read. **Assistant.** It may cite the Return card's content
through E28's plan explanation tool; it has no tool that reads or writes readiness, and nothing it says changes the state.
