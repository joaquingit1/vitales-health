### 3.2 Selection and state (CONTRACTS 27)

```python
def compute_return_readiness(subject: PersonRef, environment_id: EnvironmentId, option: ReturnOption | None,
                             runs: ReturnRuns, words_for: Callable[[str | None], ReadinessWords],
                             now: datetime) -> ReturnReadiness | NotApplicable: ...
```

1. `option is None`: `NotApplicable` (422 CONTEXT_INAPPLICABLE, EI11).
2. A return run is a run of the subject whose `environment_id` equals the active environment and that has at least one
   step of stage `return`. E28 creates those steps only when the pinned stage applied in the run's environment
   (E28 3.4), so the pinned stage necessarily lists the active environment. No activation time cutoff exists: re-entering
   the Moon base shows a run still open there, and a clock correction cannot hide a run.
3. Order: E28's commit order of the open command (X5), a strict total order unaffected by clock corrections or equal
   `opened_at`. `latest_closed` is the closed return run with the latest close commit.
4. Selected run: `latest_open` when present; otherwise `latest_closed` when any of its prepare steps is `done`; otherwise
   none. Only these two runs can ever be selected, so reading exactly two rows bounds the work without changing the result.
5. State: open run with a `done` prepare step (after 3.3): `preparing`; open run without: `open`; selected closed run:
   `preparing` when `close_disposition` is `preparing_return` (X9a), `stood_down` otherwise; no selected run: `closed`.
6. With a selected run: `criteria` are the pinned stage's criteria with `status` `unknown` and `evidence_ids` `[]`;
   `criteria_text` is `return_criteria_pending` while any criterion has `to_be_set_by` "flight rules", else `None` (the
   PlanView rule, CONTRACTS 22); `prepare` per 3.3; `decided_by` and `rtdc` (possibly `None`) from the pinned stage;
   `plan_run_id`, `plan_id` from the run; words from the run's pinned ui-copy.
7. Without one: `plan_run_id`, `plan_id`, `criteria_text`, `rtdc` are `None`, the lists are empty, words come from the
   active ui-copy (the closed example).
8. Always: `who_decides_text` from the words; `trip_text`, `trip_source_ids` from the active release's `return_option`
   (environment profiles are not run pins, CONTRACTS 11 "Versions and releases"); `environment_id`; `as_of` is `now`.

A closed return run stays the reported one (for example `stood_down`) until a newer return run opens or closes: the
contract defines no expiry, and inventing one would hide a recorded fact.

### 3.3 Prepare projection

ReturnReadiness `prepare[].state` allows only `open` and `done`; a run step can also be `not_available` or `substituted`.
Until X10 adds them, the hub projects without ever showing an unavailable step as open:

| Pinned prepare step | Run step | Listed in `prepare[]` |
|---|---|---|
| Any | Absent (it did not apply at open, CONTRACTS 22 rule 1) | Left out; never invented |
| `substitute_only` | Its principal is `not_available` or `substituted` | Listed in the principal's place with its own `open` or `done` |
| `substitute_only` | Otherwise | Left out (shown only in place of its principal) |
| Principal | `open` or `done` | As is, with `by` and `at` |
| Principal | `substituted` or `not_available` | Left out; its substitute takes its place when it has one |

The card never relies on this list for availability or actions: it draws each prepare step with E28's `StepRow` from the
PlanView step view and the PlanRun step (section 7), which carry all four states, availability and `who_can`.

### 3.4 The RTDC parser and verifier (pure)

```python
@dataclass(frozen=True, slots=True)
class FormPage: page: int; text: str

class Table4Refusal(StrEnum):
    NO_TABLE = "no_table"; AMBIGUOUS_TABLE = "ambiguous_table"; NO_TABLE_END = "no_table_end"
    TOO_LONG = "too_long"; HEADER_MISMATCH = "header_mismatch"; ROWS_MISMATCH = "rows_mismatch"
    NO_PROBABILITY = "no_probability"; CELL_COUNT = "cell_count"; NOT_A_CELL = "not_a_cell"
    RTDC_NOT_AVAILABLE = "rtdc_not_available"; OUT_OF_RANGE = "out_of_range"; MIN_ABOVE_MAX = "min_above_max"

def parse_table4(pages: Sequence[FormPage]) -> Table4 | Table4Refusal: ...
def verify_rtdc(rtdc: Rtdc, pages: Sequence[FormPage] | None) -> RtdcVerdict: ...
    # Verified | Mismatch(fields) | Refused(Table4Refusal) | SourceUnreadable
```

Grammar (refuse on any deviation, never guess; charter section 1 rule 4):

1. Exactly one line in the form starts `TABLE 4.`; its page is the Table 4 page. The table ends at the first later line
   starting `TABLE 4 KEY`, on that page or the next. At most 400 body lines (implementation bound, asserted).
2. The 25 lines after the title equal the CliFF Table 4 header exactly (`Case Scenario`, `Composite`, `Incidence`, ...,
   `Min%`, `Max%`, `Min%`, `Max%`). This is the column grammar of NASA's form layout, held in the parser like a file
   format; it carries no clinical value, and a form with another layout is refused.
3. Row boundaries: one line each ending `(TBC)`, `(TWC)`, `(UTBC)`, `(UTWC)`, in that order. A row's cells run to the next
   boundary or the key; trailing lines with no digit that are not `N/A` are the next row's label and are dropped.
4. The probability cell is the first cell that is a range (regular expression `^\d+(\.\d+)?\x20\x2D\x20\d+(\.\d+)?$`: two
   numbers joined by space, hyphen, space, as in the form's `98.67` to `98.67` cell), or, when the row starts with two `N/A` cells, the second
   `N/A`. Lines before it are the composite incidence (free text such as `1.626` `person-` `years SD: 0.1905`).
5. Exactly ten value cells follow, each a number or `N/A`: CP1 TI%, CP1 duration, CP2 TI%, CP2 duration min and max, CP3
   TI%, RTDC min%, RTDC max%, LOCL min%, LOCL max%. RTDC is cells 7 and 8 as `Decimal` (never float), within 0 to 100,
   min not above max.

`verify_rtdc` returns `Verified` only when the parsed page equals `rtdc.page` and all eight values are numerically equal;
otherwise every differing field, or the refusal, or `SourceUnreadable` when there are no pages.

**Evidence (prototype run during this design; tests still to run).** Over the fourteen saved forms with a Table 4, twelve
parse (RS07, RS10, RS14, RS24, RS28, RS29, RS32, RS33, RS40, RS43, RS52, RS55) and two are refused: RS34 (its probability
cell `99.9996 -` is split over two lines) and RS58 (its header lines are split differently). RS32 gives page 5 and treated
best 0 to 0, treated worst 96 to 100, untreated best 0 to 100, untreated worst 100 to 100, the `rtdc` of `plan_eye_injury`
and `return-readiness-tomas.json`. Deleting `RS32.txt` line 266 (the treated worst RTDC minimum `96`) is refused with
`cell_count` instead of reading 5.63 to 100. Every single line deletion and duplication inside Table 4 of the twelve
parsed forms (2,000 mutants) was either refused or left all values unchanged. Limit: a transposition of two values inside
a well formed row of the saved text still parses; the independent check of the PDF page by a second person (section 8)
is the control for that.

### 4.2 Use case `GetReturnReadiness`

Input: optional `subject`, the session. Output: ReturnReadiness. Read only; no idempotency key.

1. Resolve the subject before anything else (a crew member asking about someone else learns nothing about the place):
   omitted on a crew session is the session person; omitted on a `station` session is `SubjectRequired`; another person
   needs `crew_medical_officer` or `station`, else `SubjectOutOfScope`; an unknown person is `SubjectOutOfScope`.
2. In one `uow = UnitOfWork.read()` (one SQLite read transaction, so environment, release and runs are one snapshot):
   active environment, `return_option`, `active_release`, `return_runs`.
3. Words: `ui_copy(run.ui_copy_version)` for a selected run, else `ui_copy(active_release.versions["ui-copy"])`.
4. `compute_return_readiness`, then map to the generated response model (Decimal written as a JSON number in shortest form).

Interim until X7 provides `UnitOfWork.read()`: read the active release ID and the active environment record before and
after the run read; if either changed, recompute once; if it changed again, `SnapshotUnstable`.

| Typed error | Cause | HTTP | `code` | `retryable` |
|---|---|---|---|---|
| `MalformedQuery` | `subject` fails the `id` pattern | 400 | MALFORMED_REQUEST | false |
| `SubjectRequired` | Station session without `subject` | 400 | MALFORMED_REQUEST | false |
| (E02) | No or expired session | 401 | UNAUTHENTICATED | false |
| `RoleNotAllowed`, `SubjectOutOfScope` | Role outside `x-roles`; another or unknown subject without the role | 403 | UNAUTHORIZED_SCOPE | false |
| `ReturnNotApplicable` | No active environment, or `return_option` `null` | 422 | CONTEXT_INAPPLICABLE | false |
| `PinnedVersionMissing`, `PinnedStageMissing` | A run pins a ui-copy version E01 cannot load, or has return steps but its pinned plan has no return stage (corrupt state) | 500 | INTERNAL_ERROR | false |
| `SnapshotUnstable`, E01 `StorageBusy`, E01 `DeadlineExceeded` | Concurrent change twice; SQLite busy timeout; request deadline | 500 | INTERNAL_ERROR | true |

Every envelope (CONTRACTS 5, `error.schema.json`) carries `field_errors` `[]`, `correlation_id`, `current_state` `null`
and `supported_alternative` `null`; `message` is for logs only. No partial ReturnReadiness is ever returned.

## 5. Adapters

**Storage.** None (CONTRACTS 27: computed on read).

**Gateways.** `environment_gateway.py` (E23), `plan_runs_gateway.py` (E28), `config_gateway.py` (E01), `people_gateway.py`
(E02), `form_pages_gateway.py` (E10). In process, inside the caller's read unit; no network. Bounds: `return_runs` reads
two runs; a run's return steps are bounded by E28's 40 steps per plan (E28 5.2); words come from E01's parsed cache, never
from raw documents on the request path.

**Verifier service.** `rtdc_verification.py` implements `RtdcVerificationPort`: `FormTextPort.pages`, then `verify_rtdc`.
It runs at release proposal time and in the CLI, never on the request path.

**CLI.** `crew-health-rtdc <source_id>` prints page, the four ranges and each row's cells as JSON to paste; `--scan`
lists the saved forms with a parseable Table 4; `--check <onboard-plans.json>` verifies every non-null `rtdc` and exits
non-zero on any non-`Verified` verdict. Until X8 lands it reads the package `research/responder/RSxx.txt`, split at
`[page N]` markers, at most 2 MB per file.

## 7. User interface

Files under `ui/crew/src/features/readiness/`. Mounted in E28's plan detail and plan run screens through the slots
`return` (paper, columns 15 to 24, rows 1 to 2) and `who_decides` (deep green, row 3), UX-DESIGN 1.2 and 3.8 (X2). Slot
props: the displayed PlanView and, on the run screen, the route's `plan_run_id`.

**Planning content comes from the displayed PlanView**, which already carries the return stage (CONTRACTS 22): criteria,
`criteria_text`, prepare step views, `decided_by`, `who_decides_text`, `trip_text`, `trip_source_ids`, `rtdc`. So a lunar
plan opened before any run shows the whole Return content.

**Run state is an overlay**, fetched only when the PlanView has a return stage and its `environment_id` is the active
environment (E03 stage store): `GET /v1/return-readiness?subject=` (on the run screen the run's subject; on the plan
detail the session person, and no call from a station session), then `GET /v1/plan-runs/{plan_run_id}` when
`plan_run_id` is not null. The overlay applies only when all hold: readiness
`plan_id` equals the view's `plan_id`; readiness `environment_id` equals the view's; the run's `onboard-plans` pin equals
the view's `plan_version`; and, on the run screen, readiness `plan_run_id` equals the route's run. Otherwise the card shows
the planning content with no state and no step marks; on a version or run mismatch it adds a link to that run's screen
(`return_words.open_run`, X3) until R28-1 lets the view render at the run's pins.

| Component | Draws |
|---|---|
| `ReturnCard.vue` | Title `plan_stage_words.return`; trip line with source chips; `criteria_text`; each criterion with its source chips; the RTDC block; prepare steps, each an E28 `StepRow` given the PlanView step view and (with the overlay) the PlanRun step, so `not_available`, `substituted`, Not aboard, `who_can` and the Done control are E28's; the state word (`plan_mode_words.prepare_return` for `preparing`, `return_words.stood_down` for `stood_down`) |
| `WhoDecidesCard.vue` | `who_decides_text` |
| `NoReturnCard.vue` | PlanView `no_return_text`, verbatim, in the Return slot |
| `useReturnReadiness.ts` | Typed client from generated types through E03 `api/client.ts` |

**RTDC block.** Heading `return_words.rtdc_title`, note `return_words.rtdc_note` ("NASA's model, never a decision
rule"), a two by two table with row labels `treated`, `untreated` and column labels `best_case`, `worst_case`, each cell
`return_words.range` with `{min}` and `{max}` (X3), and the source line: a source chip for `rtdc.source_id` and
`return_words.rtdc_page` with `{page}`. Numbers are the response values in shortest form (96, 2.8, 0.33), no rounding, no
locale grouping, the same rule as `{limit_value}` (CONTRACTS 11 "Templates"). `rtdc: null` draws `return_words.rtdc_none`.
No color, icon or order encodes the chance.

**Freshness and context.** Each request carries a token (session ID, subject, plan ID, environment, counter); a response
whose token is not current is dropped, and an in-flight request is aborted when the context changes. Events are coalesced:
at most one request in flight and one pending, the latest wins. The cache is keyed by session and cleared by E03 on sign
out and crew switch. On an event stream error E03's `StaleBanner` shows and the card dims its state and step marks (never
shown as current); on reconnect, and on `410 CURSOR_EXPIRED` (E03 reloads views), the card refetches.

| State | What shows |
|---|---|
| Loading | Card frames, no text |
| Not applicable (Mars, transit) | `NoReturnCard`; no Who decides card; no readiness call |
| No run, or another plan's run | Planning content, no state, no marks |
| Open | Planning content with run marks; steps open |
| Preparing | As open, done steps with time, `prepare_return` mode word |
| Stood down | As open with the run's step states and `return_words.stood_down` |
| Version or run mismatch | Planning content, no marks, link to the run |
| Error | `error_messages[code]`, else `designed_states.unknown` (X12); never `message` |
| Stale (stream lost) | Last content dimmed under `StaleBanner`; refetch on reconnect |
| Offline or hub stopped | E29's cached PlanView return content with its release version; no state; no controls |
| LIVE, REPLAY, SIM | E28's origin swatch on the plan; readiness carries no reading |

**Actions and their reliability.** E33 has no command. A prepare step is marked through `StepRow` and E28's run client
(`POST /v1/plan-runs/{id}/actions` `step_done`, `Idempotency-Key` and `If-Match` from E03's client). Guarantees and their
owning tests: a retry after a lost response reuses the key and gets the first result (E28 T28-13); after an app restart a
new key on a `done` step is a no-op (E28 R28-15); a stale If-Match on `step_done` is merged (CONTRACTS 22); a storage
failure leaves the step `open`. E33 adds seam tests T33-19 over E28's real application to prove the card and readiness
follow each case.

**Kept out of the demo.** No flag: the demo fixture (Mara, `plan_icl10`, no return stage) never mounts the RTDC block or a
run overlay. T33-17 renders every demo act screen and asserts no Return card content and no readiness call.

**Accessibility.** Text only; the RTDC block is a table with header cells; source chips are links named by source title;
prepare steps are an ordered list; `aria-live="polite"` on the state word; no motion. **No content in client code:**
T33-16 runs the V98 scan on the feature.

**Loader integration (X4, build prerequisite).** E28's check 14f calls `RtdcVerificationPort.verify` for every non-null
`rtdc`; each non-`Verified` verdict is a `validation.errors` finding at `/plans/<i>/stages/<j>/rtdc` (or `.../rtdc/<field>`
for a mismatch) naming the verdict, so the proposal is stored `rejected` and the active release stays (CONTRACTS 11).
`SourceUnreadable` is a finding, not a pass. A null `rtdc` is not checked. E27's authoring check 3 uses the same port for
the kit map's `rtdc`. `source_id` resolves through loader check 2 (the package registry, including `| RS32 |` in
NASA-SOURCES.md, plus the document's own `sources[]`); it need not appear in `sources[]`.

**E33-01 content procedure.** For each lunar plan E28 writes:

1. `crew-health-rtdc --scan` lists its cited forms with a parseable Table 4.
2. `crew-health-rtdc <source_id>` gives the values; a second person checks them and the page against the PDF. The record
   is the plan's `checked_by` (schema-valid) and, once X18 lands, a row in E28's `authoring/plans/rtdc-checks.csv`.
3. A stage is proposed only when a criterion can be quoted from a cited source (`to_be_set_by` "flight rules"); prepare
   steps use the source's words or "to be set by flight rules", `who` `crew_medical_officer`; `decided_by`
   `["commander", "crew_medical_officer"]`; `rtdc` from step 2, or `null` when no form parses.
4. The stage goes to E28 as a proposal for its authoring file (X1); E28 regenerates `config/onboard-plans.json`.

The first stage is `plan_eye_injury`'s, exactly as in the package example (RS30, RS32; RS32 page 5).
