# E06: Personal and station cameras

Technical design for epic E06, written with the build (the brief `docs/product/tdd/E06.md` asked for one and none
existed). It records what was built and why; `docs/build/E06/PLAN.md` holds the planning history and requests C1 to
C4. Read first: `AGENTS.md`, `docs/SYSTEM.md`, `docs/DEPLOYMENT.md` and `docs/requests/COORDINATOR-DECISIONS.md`.

## 1. Scope

Delivers E06-01 (independent pulse and respiration pipelines), E06-02 (station pairing and best-view selection) and
E06-03 (quality evaluation with a separated identity experiment); requirements R09, R11 and R29; scenarios V05, V06,
V07, V08, V09, V11, V13, V16, V39 and demo assertions D08 and D09. Not delivered here: the measurement request and
attempt records (E05), observation storage (E01 records), worker supervision and restart (E20), the compression rate
analyzer (E30, `workers/camera/src/crew_health_camera/analyzers/compression_rate/`), and screens (the crew app shell
is deferred by the owner).

## 3. Domain model

Worker domain (pure): `FrameFeatures` per frame (device, clock segment, monotonic ns, luma, saturation, face count,
face colour means, shoulder heights). Decisions for pulse (POS, Wang 2017, with CHROM corroboration, de Haan 2013,
never averaged) and breathing (shoulder vertical motion) are independent: each returns `Reading` or `NoReading` with
the first failing reason of a closed set (`domain/policy.py` REASON_CODES). Peak outside the band or at the search
edge is `outside_analysis_range`, never clipped. Selection keeps every qualified view, picks the highest SNR (ties
by device ID) and flags disagreement above the configured tolerance. Pairing is explicit device configuration: each
camera names the one person it is paired with (`subject_id`); `describe` publishes the pairs, the hub starts only on
the cameras paired with the request's subject (`device_ids`, never empty), and the worker refuses any other. Pairing
admits frames only from those cameras, same segment, before expiry, not revoked; one frame with a second face makes
that camera's whole window ambiguous and none of its frames reach analysis.

Decisions the brief asked for: POS over CHROM or ICA because it needs no skin-tone tuning and is deterministic
(CHROM kept as an independent check); torso method is shoulder landmark height, not optical flow, because it is
cheap and fails visibly (`shoulders_not_visible`); pairing is explicit (the start names the subject and request),
face matching stays an offline experiment (`evaluation/identity.py`) that never authorizes a write (V39); scheduling
is one capture at a time in the worker with a bounded table.

### 3.1 Time

Worker time is its monotonic clock plus a clock segment; a segment change inside a window is `time_discontinuous`.
The hub probes the worker's UTC and computes offset and uncertainty the NTP way (`application/link.py`); the worker
reports instants in hub time (worker time minus offset) and the uncertainty travels with reference outcomes. The
offset travels with every start but is not part of its identity, so a retry after a fresh probe is the same start.
A camera opened fresh ramps its exposure and white balance for about a second (a laptop camera, measured: 1.3 s),
which buries the pulse; frames are dropped until every channel's whole frame mean changes by no more than the policy's
`capture.settled_change_per_s` against the frame one second earlier, the window counts from the first settled frame,
and a camera still changing at `workers.camera.warmup_max_ms` (sent with every start) is `camera_not_settled`.
Observed time is the end of the capture window, never arrival. A probe older than `workers.camera.stale_ms`, or from the
future after a hub clock correction, is unknown.

## 4. Application layer

Worker `AcquisitionService`: start (idempotent per acquisition ID, CONFLICT on a different body, BUSY when full,
NOT_PAIRED for a camera not paired with the subject, origin checked against `required_origin`), status, cancel,
run_next (capture, pairing, decide, select, compose), deliver_pending (Idempotency-Key `<acquisition_id>.attempt`,
capped exponential backoff, never gives up), expire. Every decided attempt is saved in the state directory before its
first delivery and reloaded after a restart; a damaged file stops the worker loudly. A persisted reference reading is
kept until a cancel names the observation it became.

Hub, all worker calls as E01 tasks outside any unit of work:

1. E05's start calls `assign` inside its unit of work. It assigns only a fresh, trusted, ready worker whose origin is
   the mission's, and records an intent keyed by the correlation ID (commits or rolls back with the start).
2. The subscriber `camera.dispatch` binds the intent to request, subject, sequence, the paired cameras and the
   required origin, and submits `camera.start` in the same unit of work. A start nothing can serve is reported.
3. `camera.start` sends the start with ttl `min(workers.camera.acquisition_ttl_ms, describe max_ttl_ms)`. BUSY or no
   answer is retried by E01's queue; any other refusal is reported. A start accepted after the request finished is
   cancelled.
4. `reconcile` runs on the camera loop. It asks the worker about each accepted acquisition and reports what ended
   there without an attempt (expired, cancelled, rejected, lost in a restart, unreachable past its deadline).
5. `camera.report` records the failed attempt through `AttemptReports` with the reason code (`camera_lost`,
   `camera_unavailable`, `camera_origin_mismatch`, `camera_not_paired`, `camera_refused_<code>` and so on), so no
   camera request stays in progress without a reason.

A failed camera attempt is final for that capture: measuring again is a new, explicit request (D08). The reference
port records a persisted reading once through `ObservationCommands` (ticket as idempotency key) before returning it,
then releases it on the worker; abandoning records a decided reading first. Every reference call is bounded by the
caller's own wait.

## 5. Adapters

Tables (`hub/src/crew_health/camera/adapters/migrations/0001_camera.sql`), STRICT: `camera_dispatch` (primary key
correlation ID, unique acquisition ID, paired device IDs, required origin, deadline; indexes on (state, updated_at)
and (request_id, sequence)) and `camera_reference` (ticket, record, persist, the observation it became, written once).
Transport: standard library HTTP with the hub to worker token from a protected file, every call bounded by
`workers.camera.timeout_ms`, replies bounded by `workers.camera.max_reply_bytes`. Worker adapters: FastAPI app, httpx
hub client, file evidence store, SIM source, and one video source (optional `capture` extra, OpenCV and MediaPipe)
for a local capture index or a network camera's MJPEG URL. The origin comes from the device: a stream that declares
`X-Device-Origin: SIM` gives SIM readings, any other camera LIVE. Configuration selects the camera; no code path
branches on a simulation flag.

The camera twin (`simulators/camera/`, its own uv project for Windows, macOS and Linux) is a simulated network camera:
`GET /cameras/<scenario>/stream.mjpg`, identity at `/identity`, SIM on every response. Scenarios: `synthetic` (a face
whose skin colour carries a 72 /min pulse and whose shoulders carry 15 /min breathing, after Verkruysse, Svaasand and
Nelson 2008), `sample` (NASA SVS 14704, public domain, fetched by `camera-twin-fetch` with its sha256 and cached
outside git), and the faults `head_motion`, `low_light`, `second_face`, `face_leaves`, `stream_drop` and `auto_exposure_ramp`
(the measured laptop camera ramp at stream start, on a face whose pulse is as weak as a real one).

## 6. API

No public hub endpoint: the worker calls E05's operation `recordAttempt` (POST
/v1/measurement-requests/{request_id}/attempts, AttemptCreate) with its adapter token and an Idempotency-Key. The worker's private protocol v1 is
documented in `workers/camera/src/crew_health_camera/adapters/protocol.py` and published as `protocol.schema.json`;
errors are `{code, detail}` with UNAUTHORIZED, INVALID, CONFLICT, BUSY, UNSUPPORTED, NO_CAMERA and NOT_FOUND.

## 7. User interface

None (crew app shell deferred by the owner). Camera name, selection, disagreement and the configured reason travel
in the attempt so E05's views can show them.

## 8. Configuration

`workers/camera/src/crew_health_camera/policy/camera-quality.json` with its schema: every limit carries a value and a
basis; provenance cites the NASA catalog for context (C09, S14, N04, `docs/product/NASA-SOURCES.md`) and states that
the catalog holds no camera photoplethysmography method or threshold, so the algorithm limits cite Wang 2017 and
de Haan 2013 and are team defaults pending PLAN C3. Reason and note wording comes from the same document. Test:
`test_policy_and_settings.py` edits a scratch copy and the served failure reason changes with no code change.

### 8.1 Activation effects

The worker loads the policy at startup and rejects a corrupt one (the worker does not start, so readiness is unknown
and manual entry stays). An acquisition keeps the policy it started with.

## 9. Deployment and fallbacks

Minimum tier: one laptop and its webcam, worker on loopback (`camera.enabled`). Worker absent, stale or untrusted:
readiness None, E05 start fails closed with `adapter_unassigned`, the pulse capability stays available through
manual entry. Worker restart mid acquisition: a decided attempt is delivered from the state directory; an undecided
one is reported Not measured (`camera_lost`), never resent blindly.

## 10. Safety, security and privacy

Frames never leave the worker; only numbers cross. The worker is authenticated by its adapter token and E05 checks
patient, method, origin and code on every value. The hub never writes a camera value. The assistant has no path to
start a capture. Logs carry exception type names only.

### 10.1 Failure and edge cases

| Case | Behavior | Test |
|---|---|---|
| Crash between start and dispatch | Intent row and its E01 task survive; dispatched after restart | `test_dispatch_rows_survive_a_restart` |

| Duplicate or retried submission | Same acquisition ID, same receipt even after the clocks moved; one attempt | `test_v16_*`, `test_a_lost_reply_*` |
| Camera still adjusting exposure when opened | Frames dropped until settled; never settled is Not measured `camera_not_settled` | `test_a_camera_still_settling_*`, `test_exposure.py` |

## 14. Requests and open questions

PLAN C1 to C4 (`docs/build/E06/PLAN.md`). Open: F1 composition binding E05's and E30's port classes, E01's
`TaskQueue` and `TaskRunner`, `MissionStatePort`, `AttemptReports` and `ObservationCommands` to these providers
(until then the camera is never assigned); E01's supervisor running registered tasks (the camera loop drains its own
three until then); person-facing copy for the hub's reason codes belongs in E03's ui-copy; the reference draft's
`operator_id` is the adapter ID; a LIVE D09 needs a real camera (the twin is SIM by design). Known limitation: on a
real face in good light the POS SNR was +0.64 dB against the 0 dB threshold (a team default, PLAN C3), so the pulse
gate has little margin on real cameras; the threshold is unchanged.
