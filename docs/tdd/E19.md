## 3. Domain model

Pure code in `hub/src/crew_health/workbench/domain/`. E10 owns `CatalogItem`, `DocumentVersion`, `ReviewState` and its
edge table; E19 owns the records that justify each edge, who may write them and which of them are in force.

### 3.1 Discovery and the outbound boundary

A denylist cannot recognize private clinical text it was never told about, so free text never reaches the network. A
research question is a set of references into a reviewed public lexicon, rendered deterministically, and the whole
serialized request is validated immediately before the socket opens.

```python
@dataclass(frozen=True, slots=True)
class LexiconTerm:
    term_id: str                                   # config_id
    text: str                                      # public wording
    kind: Literal["topic", "qualifier"]
    origin: Literal["registry_alias", "environment_hazard", "lexicon_file"]
    basis: str                                     # source ID or "team default"

@dataclass(frozen=True, slots=True)
class PublicLexicon:
    lexicon_version: str                           # SHA-256 of the canonical term list
    terms: Mapping[str, LexiconTerm]

@dataclass(frozen=True, slots=True)
class ResearchQuestion:                            # the whole discovery input: no free-text field exists
    topic_ids: tuple[str, ...]                     # 1 to query.max_topics
    qualifier_ids: tuple[str, ...]                 # 0 to query.max_qualifiers
    num_results: int                               # 1 to query.max_results
```

Lexicon sources: E10 `ConditionRegistryPort.aliases` of active conditions (NASA titles), hazard names of the active
`environment-hazards` document, and `knowledge/workbench/lexicon.json` (team-curated public phrases, each with
`basis`). `render(question, lexicon, policy) -> str` joins topic texts then qualifier texts with single spaces; over
`query.max_chars` is refused. An unknown term ID is refused before anything is stored.

`check_outbound(request: OutboundRequest, ctx: GuardContext) -> GuardResult` (pure, `domain/guard.py`) runs on the
serialized request in the adapter, after serialization and before the write:

| Rule | Blocks when |
|---|---|
| O1_shape | The body has a key outside `exa.search_body_keys` or `exa.contents_body_keys`, or a string field other than `query` and `urls` |
| O2_render | `query` is not byte-equal to `render(question)` of the query record being sent |
| O3_destination | The endpoint, a `contents` URL, a fetch target or any redirect fails the destination policy (5.2) |
| O4_roster | Any string contains a crew display name or person ID from E01's roster (casefold, accents folded, word boundaries); read at send time, so a name added after the lexicon loaded still blocks |
| O5_mission | Any string contains the mission ID or a stamp matching the mission clock document's MET pattern |
| O6_catalog_url | A URL that is not the normalized URL of a catalog item (or a redirect hop of it) |
| O7_headers | A header outside `exa.header_allowlist`; the user agent is the fixed generic value in policy |

The lexicon loader runs O4 and O5 over every term and rejects a lexicon that fails. `addResearchSource` runs O4 and O5 on
the URL it registers. Structural lines around the guard: the workbench has no import path to records, journal, reports,
episodes, participation or the vault (import-linter), the editor session has no patient scope (CONTRACTS section 20),
and the editor sees the rendered text in state `prepared` before sending.

What is kept: a rejected or blocked submission stores only `GuardRejection {rejection_id, actor, at, rule_ids,
term_count}`; no text, no hash of text. A prepared query stores its question (term IDs), rendered text and lexicon
version, all public by construction.

```python
class QueryState(StrEnum):
    PREPARED = "prepared"; SENT = "sent"; SUCCEEDED = "succeeded"; FAILED = "failed"
    OUTCOME_UNKNOWN = "outcome_unknown"; CANCELLED = "cancelled"

@dataclass(frozen=True, slots=True)
class DiscoveryQuery:                              # immutable header
    query_id: str                                  # injected IdGenerator, never derived from time
    provider: Literal["exa", "import"]
    question: ResearchQuestion | None              # None for an imported file
    rendered_text: str
    lexicon_version: str | None
    policy_sha256: str
    request_blob_sha256: str | None                # exact body, archived before the send
    created_by: ActorRef
    created_at: datetime
    retry_of: str | None

@dataclass(frozen=True, slots=True)
class QueryEvent:                                  # append only; current state is the last event
    seq: int
    query_id: str
    to_state: QueryState
    at: datetime
    response_blob_sha256: str | None
    error_code: str | None                         # NO_RESPONSE, HTTP_<status>, DEADLINE, BODY_TOO_LARGE, INTERRUPTED
```

| From | To | Trigger |
|---|---|---|
| (new) | prepared | Question valid, render passes, O4 and O5 pass on the text |
| prepared | cancelled | Editor cancels |
| prepared | sent | Committed before the socket opens (write ahead), with the request blob |
| sent | succeeded | Response archived, results committed |
| sent | failed | Final error after bounded retries, including no response within the deadline (`NO_RESPONSE`) |
| sent | outcome_unknown | Cancelled in flight, or found in `sent` at startup (`INTERRUPTED`): the request may have reached the provider |
| (new) | succeeded | Import of a saved discovery file (no send) |

Terminal states never change and are never retried automatically; a retry is a new query with `retry_of`.
`DiscoveryResult {query_id, rank, url, title, published_date_text, catalog_item_id}` is immutable;
`published_date_text` is kept as the provider gave it and never parsed into a fact.

### 3.2 Records bound to content

Every review binds to the exact content it judged. A target is `(document_version_id, content_sha256)` for a completeness
assessment and a license record, and `(document_version_id, content_sha256, text_sha256)` for a technical check and a
clinical review.

```python
class ReviewKind(StrEnum):
    TECHNICAL_CHECK = "technical_check"; CLINICAL_REVIEW = "clinical_review"

class Attestation(StrEnum):
    LICENSED_CLINICIAN = "licensed_clinician"; TEAM_MEMBER_NOT_CLINICIAN = "team_member_not_clinician"

@dataclass(frozen=True, slots=True)
class CompletenessAssessment:
    assessment_id: str
    document_version_id: DocumentVersionId
    content_sha256: str
    completeness: Completeness                     # at most the rule ceiling of 3.3
    evidence: CaptureFacts                         # retrieval method, bytes, truncation, page count, media type
    assessed_by: ActorRef
    at: datetime

@dataclass(frozen=True, slots=True)
class SourceReview:
    review_id: str
    document_version_id: DocumentVersionId
    content_sha256: str
    text_sha256: str
    kind: ReviewKind
    reviewer: ActorRef
    verdict: Literal["pass", "fail", "revoked"]
    completeness_confirmed: Completeness | None    # technical_check: equal to or below the assessment
    source_kind: SourceKind | None                 # technical_check, never "unclassified"
    applicability: Applicability | None            # technical_check; unknown stays unknown
    attestation: Attestation | None                # clinical_review, required there
    notes: str
    at: datetime
    supersedes_review_id: str | None               # same target and kind

@dataclass(frozen=True, slots=True)
class LicenseRecordRef:
    license_id: LicenseId                          # E10 LicenseRecord
    document_version_id: DocumentVersionId
    content_sha256: str
    permission_basis_url: str | None               # documented redistribution permission (OD-3)
```

**Effective review.** For one target and kind, the heads are the reviews no other review supersedes. The effective
verdict is `none` with no head, `fail` if any head is `fail` or `revoked`, otherwise `pass`. A correction is a new review
naming `supersedes_review_id` of the same target and kind, written by any editor except the extractor; a revocation is a
correction with verdict `revoked`. A new extraction (another `text_sha256`) leaves the old text's reviews in history and
gives the new text no review.

**Claims are versioned.** `Claim {claim_id, context}` is the stable identity; `ClaimRevision {claim_rev_sha256,
claim_id, text, source_ids, spans, superseded_span, current_span, limitation, author, claims_file_sha256}` where
`claim_rev_sha256` is the SHA-256 of the canonical body. Contexts: `documentation`, `passage_support`, `pathway_card`,
`discrepancy`. A discrepancy is directed: `superseded_span` is a span approved in the previous release,
`current_span` a span of an approval in the promotion (V24).

```python
@dataclass(frozen=True, slots=True)
class ClaimReview:
    claim_review_id: str
    claim_rev_sha256: str                          # binds the exact revision
    reviewer: ActorRef                             # never the revision author
    verdict: Literal["supported", "partially_supported", "unsupported", "contradicted", "revoked"]
    qualification: str | None                      # required for partially_supported, rendered beside the claim
    relation: Literal["contradicts", "revises"] | None   # required for context discrepancy
    notes: str
    at: datetime
    supersedes_claim_review_id: str | None
```

Effective claim verdict uses the same head rule; `unsupported`, `contradicted` and `revoked` dominate.

**Per-use approvals** (CONTRACTS section 4: "Approval belongs to a version and purpose"):

```python
@dataclass(frozen=True, slots=True)
class UseApproval:                                 # immutable; one use per approval
    approval_id: str
    target: DocumentTarget | PathwayCardTarget
    content_sha256: str | None
    text_sha256: str | None
    use: AllowedUse
    spans: tuple[Span, ...]
    partial_acknowledged: bool
    assessment_id: str | None
    technical_check_id: str | None
    clinical_review_id: str | None
    license_id: LicenseId | None
    policy_sha256: str                             # release-policy.json the pre-check used
    approved_by: ActorRef
    approved_at: datetime
    supersedes_document_version_id: DocumentVersionId | None

class ApprovalState(StrEnum):
    ACTIVE = "active"; SUPERSEDED = "superseded"; WITHDRAWN = "withdrawn"
```

Approval events (`active`, `superseded` with the superseding approval, `withdrawn` with `reason_code` and `reason`) are
append only; the approval's `revision` is its event count. An approval is **in force** only while its last event is
`active`, every pinned review is a head with verdict `pass`, its `text_sha256` equals the version's current extraction
and its license record is the effective one. An approval not in force is reported as a finding at promotion, never
dropped silently.

### 3.3 Workflow rules

| Action | Allowed when | Internal error |
|---|---|---|
| Capture | Network on for fetch, or the file inside an import root (5.2); bytes, media type and archive admission within policy | `CaptureRefused(reason)`, `CaptureOff` |
| Assess completeness | Any editor; value at most the rule ceiling below | `AssessmentAboveCeiling` |
| Extract | Effective assessment is `full` or `partial`; media type supported | `ExtractionRefused`, `ExtractionTimeout`, `ExtractionFailed` |
| Technical check pass | Reviewer is not the extractor; `completeness_confirmed`, `source_kind` set; an effective license record exists | `ReviewerIsAuthor`, `ReviewIncomplete` |
| Clinical review | Reviewer is not the extractor; attestation set; allowed on `technically_checked`, `clinically_reviewed` or `approved` versions | `ReviewerIsAuthor`, `ReviewIncomplete` |
| Use approval | Approver is not the extractor; the policy row for the use holds (E10 3.5) over in-force reviews; spans inside the current text; rule L1 | `ReviewerIsAuthor`, `PolicyNotMet(use, rule)` |
| Withdraw approval or version | Any editor; `reason_code` from policy and a non-empty reason | `ReasonRequired` |
| Supersede link | Newer version of the same catalog item, or two items linked by an editor with a reason; never by title alone | `SupersedeInvalid` |
| Claim review | Reviewer is not the revision author | `ReviewerIsAuthor` |
| Promote | Every approval in force; every pinned review has its audit event in E01's chain; E10 builder accepts all | `ApprovalNotInForce`, `ReviewNotAudited`, `BuildRejected(findings)` |
| Activate, roll back | `operator` or `editor`; a reason; activation carries the release record revision | `InvalidTransition`, `StaleVersion` |

Every action on an object with a revision also takes the expected revision (`StaleVersion`). There is no override flag.

**Completeness ceiling of a captured version** (`assess_ceiling(facts) -> Completeness`, pure). E10's
`completeness_ceiling` on a catalog item describes provenance without a blob; it never gates a version. A version's
eligibility comes from its own capture facts:

| Retrieval method and facts | Ceiling |
|---|---|
| `http_fetch`, `file_import`, `audit_pdf`, `package_saved_text`: complete transfer (length matched or clean end of stream), document media type, PDF page count above zero | full |
| Same methods, transfer stopped at `fetch.max_bytes` | partial |
| `exa_contents` (third-party text, may be cut at `exa.text_max_characters`) | partial |
| Search result text or highlights | summary_only (never extractable) |
| Fetch failed or access blocked | inaccessible (no version is created) |

So a catalog-only discovery followed by a complete fetch can reach `full`, while a search summary never can.

**License rule L1 (OD-3).** Passage text may be approved only when the effective license record is
`us_government_public_domain`, or `open_license` with `permission_basis_url` set. Any other source ships metadata only:
title, citation, link and content SHA-256.

**Display status** (`display_status(facts) -> ReviewState`, pure) is the single aggregate shown for a version and in
`ResearchSource.status`: `withdrawn` if withdrawn; `superseded` if every approval ever made is superseded; `approved` if
any approval is in force; else `clinically_reviewed`, `technically_checked`, `extracted`, `captured` by the furthest
in-force record; `discovered` with no version.

### 3.4 Literature-update policy

Values in `knowledge/workbench/policy.json` `update`:

1. **Watch.** `crew-health-workbench recheck` (manual, or every `update.recheck_interval_days` on a networked ground
   host) fetches each registered URL conditionally (ETag, Last-Modified) and compares the SHA-256 with the latest
   version.
2. **A change is a new version.** Changed bytes create a new captured version; approvals of the old version stay in
   force until the new one is approved; the workspace lists the source under "Changed at source".
3. **Supersession is explicit and per use.** Approving the new version for use U with `supersedes_document_version_id`
   appends `superseded` to the old approval for U only; other uses of the old version stay in force. A contradiction is
   recorded as a discrepancy claim with its review (V24).
4. **A broken link never withdraws by itself.** `update.broken_after_failures` consecutive failures mark `link_broken`;
   withdrawal is an editor action with a reason.
5. **Revision letters.** A NASA document reissued under a new revision letter (NASA-SOURCES section 4: NASA-STD-3001
   Volume 2 Rev F replacing revisions cited by C25) is linked by `supersedes` with the reason; both stay in history.
6. **Discovery never approves.** An Exa result is `discovered` until captured, assessed and reviewed.
7. **Releases move forward on the ground** and reach flight hubs as files; a flight hub activates when its operator
   chooses and keeps the previous release for rollback.

```python
@dataclass(frozen=True, slots=True)
class DocumentationRelease:
    doc_release_id: str                            # "docr_" + 16 hex of the output manifest body
    pins: DocPins                                  # evidence_release_id, registry_version, config_release_id, kit_map_versions, eval_run_ids, policy_sha256, claims_file_sha256
    items: tuple[ItemStatus, ...]
    claims: tuple[ClaimOutcome, ...]               # claim_id, claim_rev_sha256, effective verdict, published or the finding
    link_checks: LinkCheckSummary                  # ok, redirected, broken, accepted_broken, not_checked
    licenses: Mapping[LicenseKind, int]
    outputs: tuple[OutputFile, ...]                # path, SHA-256
    state: Literal["failed", "preview", "publishable"]
    findings: tuple[DocFinding, ...]
```

| State | When |
|---|---|
| failed | An E19 output cannot be generated: unknown claim or table marker, unreadable input |
| preview | Generated, but a required item is missing, links were not checked online, a broken link is not accepted with a note, a source lacks a license record, or a referenced claim is not publishable |
| publishable | Every required item present, every link checked online and ok or `accepted_broken` with a note, every source with a license record, every referenced claim publishable |

A claim is publishable when its effective verdict is `supported`, or `partially_supported` with its qualification
rendered; it resolves to at least one source or approved span; its limitation is non-empty. A discrepancy claim is
publishable with `supported` and a relation. Only a `publishable` release satisfies E19-03; previews stay available.

### 3.7 Review status and coverage

`coverage.json` follows VALIDATION section 4 ("Report `listed`, `intake`, `authored`, `reviewed`,
`equipment_available` and `evaluated` counts separately"). Every count is `{value: int | null, denominator: int | null,
state: "measured" | "not_measured_yet", source, pins}`; `value: 0` only when measured, `null` with `not_measured_yet`
otherwise.

| Count | Formula | Denominator | Source |
|---|---|---|---|
| `listed` | Active conditions | Same (119 today, computed) | `ConditionRegistryPort.counts().active_conditions`, plus `memberships_total` labeled "inventory rows, not diseases" |
| `intake` | Active conditions whose family has an intake question set | Active conditions | E04 `IntakeCoveragePort` (14.9) |
| `authored` | Active conditions whose pathway card in the pinned release has `workup_review_required == false` | Active conditions | `EvidenceQueryPort.pathway_card` |
| `reviewed` | Active conditions whose pathway card `review_state == "reviewed"` | Active conditions | Same |

### 4.2 Use cases and command identity

Command identity and content deduplication are separate. **Command identity:** the idempotency record key is `(actor_id,
operation, Idempotency-Key)` with `body_sha256` of the canonical command (every input, including `dry_run`, link mode,
expected revision and the policy SHA-256); the same key and body return the stored result, a different body
`DuplicateCommand`; records are kept `commands.retention_hours` (CONTRACTS section 5: 24 hours). The CLI takes
`--idempotency-key` or generates one and prints it for a retry. **Content deduplication** returns the existing object
with `deduplicated: true` and is not an error.

| Use case | Input (plus key) | Expected revision | Content dedup | Internal errors |
|---|---|---|---|---|
| `PrepareQuery` | ResearchQuestion | none (creates) | none | `UnknownTerm`, `GuardBlocked`, `DiscoveryOff` |
| `SendQuery` (job) | query ID | query revision | none | `InvalidTransition`, `DiscoveryOff`, `CallFailed` |
| `ImportDiscoveryFile` | path | none | file SHA-256 per provider `import` | `ImportRefused`, `InvalidFile` |

### 4.3 Transactions, audit and recovery

One command is one transaction (CONTRACTS section 20, "Rules for every module"):

1. Blobs first: `BlobStore.put` writes a temporary file, fsyncs it, links it into place write-once and fsyncs the
   directory. An unreferenced blob after a crash is harmless (content addressed) and listed by `reconcile`.
2. One `ResearchStorePort.research_tx()` (`BEGIN IMMEDIATE` on `research.sqlite`) holds the E19 records, the E10 catalog
   change made with the same `tx`, the outbox row and the command record. Commit, then acknowledge.
3. The audit relay forwards outbox rows to E01 with `dedup_key = "wb:" + outbox_id` and appends the acknowledgement; at
   startup and every `audit_relay.interval_s`. A crash between E01's append and the acknowledgement is absorbed by the
   dedup key.

Interim while E10 lacks a shared `tx` (request 14.2): the E19 transaction commits the records, outbox and command with
a `pending_effect` row; the E10 call follows (idempotent through expected revision and the review reference); an
`effect_done` row closes it. `reconcile` re-drives pending effects at startup and before every promotion; promotion is
refused while any effect is pending, and the workspace shows "review recorded, state pending".

Promotion: `building` is committed with `input_sha256` before E10 `build` runs; `built` with bundle path and manifest
SHA-256 after. Activation: E10 commits its own transition (hub database) and audit; E19 then refreshes its projection.

**Startup reconciliation** (`crew-health-workbench reconcile`, also run by the worker at start): queries in `sent`
become `outcome_unknown` with `INTERRUPTED`; promotions in `building` become `interrupted`; jobs in `running` become
`failed` with `INTERRUPTED`; pending effects are re-driven; the outbox drains; promotion projections refresh from E10;
directories under `docs/research/.staging/` are removed.

**Documentation publication.** A build writes into `docs/research/.staging/<doc_release_id>/`, fsyncs, then renames the
directory to `docs/research/releases/<doc_release_id>/` (one rename on one filesystem). `PublishDocumentation` replaces
`docs/research/pointers.json` (`{publishable, latest, latest_state, revision}`) by temporary file, fsync and `os.replace`,
then `index.md` the same way. `latest` moves on every successful build; `publishable` only on publish. Release
directories are immutable; `docs.retained_releases` are kept, never the two pointed to.

Disk full: `DiskPort.admit` refuses a write that would cross `archive.quota_bytes` or `archive.min_free_bytes` before it
starts; `SQLITE_FULL` or `ENOSPC` inside a transaction rolls it back and returns `StorageRefused`. In both cases nothing
was acknowledged.

### 4.4 Jobs and the worker

Long work (`SendQuery`, `Capture`, `Extract`, `Recheck`, `Promote`, `BuildDocumentation`) is a workbench job in
`research.sqlite`, run by `crew-health-workbench worker`, a separate process supervised by E01 (request 14.4): health
check, restart with backoff, at most `jobs.restart_max` restarts in `jobs.restart_window_s`, then the workbench reports
itself down. One job runs at a time; the queue holds at most `jobs.queue_bound`; a full queue refuses with `Busy`.
Cancellation appends `cancel_requested`; the worker cancels the in-flight network call through its cancel scope and kills
an extraction child with `SIGKILL`, within `jobs.cancel_latency_s`. Archived items stay archived.

### 5.2 Input boundaries

**Import roots.** `ImportPort` reads only under `CREW_HEALTH_WORKBENCH_IMPORT_ROOTS` (default: E10's
`knowledge/inputs/`, the hash-guarded package copies), never under the data directory or the E18 vault root even when
listed. Each read opens the root directory and walks the relative path component by component with
`openat(O_NOFOLLOW | O_CLOEXEC)`, refusing `..`, absolute components, symlinks, non-regular files, files with more than
one hard link, and a final `fstat` whose device and inode differ from the walked one. Only the named file is opened;
nothing lists directories. Size bound `import.max_file_bytes`, result bound `import.max_results_per_file`.

**Destinations.** Every fetch, link check and Exa call goes through one `httpx` client with `trust_env=False`, no
credentials, schemes in `fetch.schemes` (`https`), ports in `fetch.ports` (443), no userinfo. The host is resolved by an
injected resolver; every address must lie outside `fetch.blocked_networks` (loopback, RFC 1918, link local including
169.254.169.254, CGNAT, multicast, unspecified, ULA, IPv4-mapped forms; a list in policy with its basis); the connection
goes to that checked address with the original host for TLS and `Host`, so a later DNS answer cannot redirect it.
Redirects are followed by hand, at most `fetch.max_redirects`, each hop checked the same way and by O3 to O6.

**Extraction sandbox.** `extract_subprocess.py` starts a child with an empty temporary working directory, a cleared
environment, `RLIMIT_AS`, `RLIMIT_CPU`, `RLIMIT_FSIZE` 0 and `RLIMIT_NOFILE` from policy, `nice` 10, and, on Linux, a
new network namespace when `unshare` is available. The child receives the bytes on stdin and the media type as an
argument; it never receives a path. Output is read up to `extraction.max_output_chars`; more kills the child with
`ExtractionFailed(output_too_large)`. Text uses E10's `=== page N ===` format.

### 5.3 External calls and bounds

| Call | Adapter | Deadlines | Retries | Bounds |
|---|---|---|---|---|
| Exa search | `adapters/exa.py`: `POST exa.search_url`, body keys `query`, `numResults`, `type`, `contents.text.maxCharacters`, header `x-api-key` from `EXA_API_KEY` | connect `exa.connect_s`, read `exa.read_s`, total `exa.total_s` including retries | `retry.max_attempts` on 429 and 5xx; backoff `retry.backoff_s`; `Retry-After` honored up to `retry.max_retry_after_s`, above it the call fails at once | `exa.rate_per_s`; `numResults` at most `query.max_results`; body read streaming, aborted past `exa.max_response_bytes` |

The Exa adapter is enabled exactly when `EXA_API_KEY` is a non-empty value in the process environment (OD-1); without it
the adapter is `Disabled` and raises `DiscoveryOff` without opening a socket, and discovery uses saved discovery files
and imports. `CREW_HEALTH_WORKBENCH_NETWORK` (default `off`) governs only web capture, recheck and link checks; with it
off those adapters are `Disabled`. The key is read from the process environment only: no configuration document,
schema or settings file has a field for it, no `.env` file is read, and it is never written to a document, blob, log or
audit event; archived requests have the header removed.

Saved discovery files: package `sources/P0x-*.json` (`{tool, args: {query, numResults}, response: {result: {content:
[{type, text}]}}}`, text blocks of `Title:`, `URL:`, `Published:` lines) and audit `01_*.json` to `09_*.json`,
`F01_*.json`, `F02_*.json`. The parser is a pure, property-tested function; an unparseable block is archived and
reported, never guessed.

**Loader.** Reads the file bytes once; validates the schema, then semantic checks (positive bounds; each total deadline
at least its connect plus read; CIDRs parse; media types in the extractor's supported set; reason codes unique; lexicon
terms pass O4 and O5; claims have non-empty limitations and resolvable source IDs through
`SourceRegistryPort.resolve_many`; template markers name existing claims and tables; items name an owner). Valid: the
immutable snapshot with its SHA-256 replaces the previous one in one reference swap. Invalid: rejected with findings, the
last good snapshot stays active, the health line and the CLI report it. No valid snapshot at start: the workbench reports
itself down and every command returns `CAPABILITY_UNAVAILABLE`; the hub is unaffected. Each job, query, promotion and
documentation release records the `policy_sha256` it started with and uses that snapshot to the end.

Configuration edits change behavior with no code change: T-E19-29 (lowering `query.max_topics` refuses a question that
passed; editing a claim's limitation in `claims.json` changes the annex; removing an item from `items.json` changes the
navigation and the preview findings; editing `release-policy.json` changes the `ApproveUse` pre-check).

Flight hubs never search the internet (LLM-ARCHITECTURE section 3). The workbench is on no critical path: no safety
function, view or record path reads workbench state, so a stopped or crashed worker changes nothing for the crew, and

|---|---|
| Language model | No effect: the workbench never calls it |
| Exa key | Discovery by Exa is off and says so; saved discovery files and imports are the sources |

| A second editor | Nothing can be checked or approved; the workspace says a second editor is needed |

Backups (AGENTS.md section 2): a wrong release rolls back to the previous verified one (INV-E19-08); a documentation
build that fails or stays preview leaves the last publishable release in place (INV-E19-14).

## 10. Safety, security and privacy

| Hazard | Cause | Mitigation | Test |
|---|---|---|---|
| Crew data sent to an internet service | Free text with a narrative, a name or an ID | No free-text input; lexicon-only render; O1 to O7 on the whole request; no read path to private stores; rejections keep no text | T-E19-01 to 04 |
| Private files pulled into the research store | Import path traversal, symlink, adjacent hidden file (V33) | Import roots, component walk without following links, data and vault roots denied, child gets bytes only | T-E19-06 |
| Request to an internal service | URL to localhost, private ranges, metadata service, rebinding, redirect | Destination policy with pinned addresses on every hop | T-E19-07 |
| An acknowledged record lost or a partial release visible | Crash, disk full between writes | One transaction, write-ahead `sent`, outbox, reconciliation, atomic pointers | T-E19-08, 09 |
| Unreviewed or stale text reaching crew guidance | Self-approval, direct database edit, review of other content | Separation of duties, content-bound reviews, in-force rule, audit cross-check, E10 re-check | T-E19-11 to 16 |
| Superseded guidance served as current | New version not linked | Explicit per-use supersession, directed discrepancies, E10 filters | T-E19-19, 20 |
| A published claim overstating its support | Contradicted or unreviewed claim in prose | Publishable rule; previews only otherwise | T-E19-14, 23 |
| Copyright breach | Non-NASA excerpts shipped | L1: metadata only without documented permission | T-E19-24 |
| Hostile PDF or HTML | Capture | Bounded child, bytes only, text as data (V22) | T-E19-26 |
| API key leakage | Logs or archive | Header stripped, environment only | T-E19-27 |
| Workbench load slows help | Heavy jobs on the hub host | Separate process and SQLite file, nice, bounded work | T-E19-28 |

Authorization: every workbench operation requires an `editor` session; release activation and rollback also accept
`operator`. Observability: logs and audit carry IDs, counts, durations, hashes and reason codes; never query text, term
lists, claim text or passage text (request 14.4 also keeps request bodies of research operations out of E01's logs).
The assistant has no access to the workbench: no tool reads the research store; E12 tools read only the active release
through E10. Named assumptions: no clinical review exists (OD-2, pending); Exa runs only with a key in the environment and only on
lexicon questions (OD-1); non-NASA text is metadata only (OD-3).
