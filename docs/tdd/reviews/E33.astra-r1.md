VERDICT: CHANGES REQUESTED

1. **[blocker] Sections 3.1, 3.2 and 7: prepare-step projection loses valid states and applicability.**  
   E33 reduces prepare steps to IDs and text, then assumes their run state is `open` or `done` ([E33:89](docs/tdd/E33.md:89), lines 143 to 147). However, [plan-run.schema.json:79](api/schemas/plan-run.schema.json:79) also permits `"not_available"` and `"substituted"`. ReturnReadiness permits only the first two states. Additionally, CONTRACTS.md:1247 says, “Steps that do not apply are left out,” and line 1250 prohibits showing unavailable steps as doable.  
   **Required change:** request an explicit resolution of the response-schema mismatch. Preserve applicability, availability and substitution through E28's step projection. Never convert unavailable states to `open` or invent a missing run step. Test all four states, inapplicable steps, unavailable equipment and an unavailable medical officer.

2. **[blocker] Section 3.3: the RTDC parser can accept shifted clinical values.**  
   The “last four tokens” algorithm at [E33:173](docs/tdd/E33.md:173) does not establish that those tokens occupy the correct columns. In [RS32.txt:265](research/responder/RS32.txt:265), the tail is `5.63, 96, 100, 0, 0`. An in-memory check removing the RTDC minimum at line 266 makes the specified algorithm read RTDC as `5.63..100` instead of `96..100`; both resulting ranges pass numerical bounds and ordering checks.  
   **Required change:** specify structural validation of headers, row boundaries and column occupancy before extracting values. Reject missing, additional, duplicated or ambiguous cells. Add corruption properties derived from the saved forms, including this deletion, rather than relying on synthetic round trips.

3. **[blocker] Sections 8 and 14: X4 permits bypassing the runtime release safety check.**  
   [E33:541](docs/tdd/E33.md:541) allows C33-2 to run only in `validate_contracts.py` until integration lands. That cannot enforce the claimed runtime rejection of incorrect or unreadable RTDC sources. [CONTRACTS.md:527](CONTRACTS.md:527) requires the loader to reject releases when its checks fail; check 14 includes saved-form provenance.  
   **Required change:** make atomic loader integration a prerequisite for activating return-stage content. Specify the validation result, source-read failures and last-good-release behavior. Test rejection through the actual release proposal and activation path. Expose verification through an application port, rather than having another module import `readiness.domain.rtdc`, contrary to charter section 3.2.

4. **[major] Section 8: the source lookup and review-record location contradict the configuration schema.**  
   C33-2 requires the RTDC source to be a CliFF in `sources[]`, and the authoring procedure records a check in a stage's “`basis` note in `sources[]`” ([E33:418](docs/tdd/E33.md:418)). The package's eye-injury example uses RS32, while its local `sources[]` contains only SK01 and SK02. The schema describes this list as sources “not yet in the package source registry” and permits `note`, not a stage `basis` note ([config-onboard-plans.schema.json:22](api/schemas/config-onboard-plans.schema.json:22)).  
   **Required change:** resolve sources through the package registry plus document-local sources. Name a schema-valid location for the independent PDF check, requesting a new shape if necessary. Verify that the unchanged package example passes.

5. **[major] Sections 3.1, 3.5 and 8: valid `rtdc: null` content has no supported behavior.**  
   E33 makes `ReturnStage.rtdc` mandatory and requires every return stage to have verified numerical values ([E33:104](docs/tdd/E33.md:104)). [config-onboard-plans.schema.json:870](api/schemas/config-onboard-plans.schema.json:870) explicitly permits an RTDC object or `"type": "null"`; PlanView and ReturnReadiness preserve that possibility.  
   **Required change:** support absent RTDC values in the domain, loader, response and UI without manufacturing numbers or removing otherwise valid criteria. If E33 intends to prohibit this package-supported state, request that restriction explicitly. Add a configuration-derived null-RTDC test.

6. **[major] Sections 3.1, 4.2 and 8: environment configuration is incorrectly pinned to an old activation.**  
   E33 reads `return_option` from the release under which the environment was activated ([E33:266](docs/tdd/E33.md:266)). Consequently, a new release cannot update trip wording or return applicability without another environment activation, contradicting T33-13. [CONTRACTS.md:1052](CONTRACTS.md:1052) defines engines as functions of the “active configuration release”; the run's enumerated pins at line 1269 do not include environment-profiles.  
   **Required change:** resolve the active environment's return option from the current release while retaining the run's specified plan and ui-copy pins. Test release activation without an environment switch, including a coordinated release that removes return applicability.

7. **[major] Sections 3.2 and 4.1: run selection can discard or change readiness without a corresponding clinical action.**  
   The activation-time cutoff excludes an otherwise active run after reactivation or a backward clock correction. The closed-history limit can discard the last relevant return run after unrelated runs accumulate. Equal `opened_at` timestamps have no tie-breaker ([E33:137](docs/tdd/E33.md:137), lines 249 to 254). Yet [CONTRACTS.md:1442](CONTRACTS.md:1442) defines `closed` as “no such run is active,” not “no run survived this cutoff.”  
   **Required change:** remove the unsupported lifetime cutoff or obtain an explicit lifecycle contract. Define a stable total ordering and a bounded query that finds relevant candidates without truncating away their meaning. Test clock corrections, equal timestamps, environment re-entry and relevant history beyond the configured limit.

8. **[major] Section 7: the planning card incorrectly depends on an existing run.**  
   The closed state hides criteria and preparation steps, so opening a valid lunar plan before starting it loses the required Return content. The mismatch fallback also assumes PlanView names a run ([E33:382](docs/tdd/E33.md:382)), but [plan-view.schema.json:940](api/schemas/plan-view.schema.json:940) has no `plan_run_id`. [UC26:286](USE-CASES.md:286) requires the plan detail to show criteria, modeled values, trip and preparation.  
   **Required change:** render planning content from the displayed PlanView and overlay run state only when explicitly matched to the selected run, plan, environment and versions. Specify the E28 component inputs. Test no run, another plan's run, two runs of the same plan and an older pinned run.

9. **[major] Sections 7, 14 and 15: the permitted interim omits required R60 content.**  
   X3 allows the entire RTDC block to remain absent, and the build completion criteria permit that result ([E33:391](docs/tdd/E33.md:391)). [PRD.md:536](PRD.md:536) requires lunar plans to show “NASA's modeled chance from the form's Table 4”; UX-DESIGN.md:476 requires its contextual label. The proposed `{min}` and `{max}` placeholders also need authorization under loader check 13, which currently rejects placeholders in unlisted fields.  
   **Required change:** make the complete X3 schema, copy and template-rule change a delivery prerequisite. Specify percentage formatting and RTDC source/page presentation. Require tests showing all four labeled ranges and an explicit stood-down state. A safely hidden block is an interim condition, not completion of R60.

10. **[major] Sections 4.2 and 6: error behavior conflicts with the wire contract and leaves valid sessions undefined.**  
    E33 puts `{environment_id}` in a 422 `current_state` and says there is “no `supported_alternative`” ([E33:351](docs/tdd/E33.md:351)). [error.schema.json:90](api/schemas/error.schema.json:90) requires `current_state` to be null outside its listed cases, and line 134 requires the `supported_alternative` property. A station session may have no person, so defaulting an omitted subject to the session person is also undefined.  
    **Required change:** return both fields as null where required, and define the missing-subject error for personless sessions. Specify typed failures for missing pins, corrupt state and adapter failures, with exact HTTP mappings. Record the charter's RFC 9457 conflict as a request rather than silently changing the package envelope. Provide configured error-copy fallbacks: the supplied ui-copy lacks several codes E33 indexes directly.

11. **[major] Sections 4, 7 and 12: concurrent reads and disconnected clients can show obsolete readiness as current.**  
    E33 specifies separate environment, configuration and run reads without a coherent snapshot, and gives no rule for late responses after a subject or environment switch. It also omits event-stream disconnect/recovery handling and uses the nonexistent `plan_run.updated` event in its sequence diagram ([E33:304](docs/tdd/E33.md:304)). [CONTRACTS.md:1007](CONTRACTS.md:1007) names `plan_run.changed`, `plan_run.step_done` and `plan_run.escalated`; lines 981 to 982 define resume and deduplication.  
    **Required change:** specify a consistent read snapshot through the owning ports, response invalidation on context changes, session-scoped caches, stale-state presentation, bounded refetching and cursor-expiry recovery. Include `config.release_activated`. Test reordered responses, two-client changes, SSE loss, logout and crew switching.

12. **[major] Sections 7, 9 and 12: the preparation action lacks a complete reliability handoff.**  
    X2's `stepDone(planRunId, stepId, revision)` and the tests do not define preservation of an idempotency key after an uncertain response, reconciliation after restart, or the outcome of disk-full and concurrent commands ([E33:539](docs/tdd/E33.md:539)). [CONTRACTS.md:210](CONTRACTS.md:210) requires an idempotency key, and line 1284 requires stale step actions to merge.  
    **Required change:** document E28's complete action-client contract and name the owning fault tests. Add seam tests for commit followed by lost response, retry after restart, disk-full rejection and two-client completion. Also verify that an incapacitated subject, including the medical officer, cannot be offered their own preparation action. These tests can exercise E28's implementation without duplicating its storage logic.

13. **[major] Sections 4, 5, 11 and 14: resource limits and failure boundaries remain unspecified.**  
    “Every” open run is returned, while its bound is merely attributed to E28; no exact bound or overflow behavior is supplied. There are no deadlines for gateway calls or form reads, and X13 introduces a “constant default inside the settings loader” ([E33:479](docs/tdd/E33.md:479), line 550). Charter sections 3 and 4 require typed boundaries, bounded work and call timeouts.  
    **Required change:** define validated settings and provenance for limits and deadlines, their owning schema, cancellation and typed exhaustion behavior. Specify startup parsing of pinned documents so raw mappings are not repeatedly parsed on requests. Ensure limits bound resource use without silently changing run selection. Add stalled-call and maximum-input tests.

    X1 proposes patches to generated `config/onboard-plans.json`. But [E28:527](docs/tdd/E28.md:527) generates that file from `authoring/plans/`, and line 656 requires byte equality with generator output. E28 also declares `PlanRunQueryPort.open_run_with_return_stage`, not E33's history interface ([E28:394](docs/tdd/E28.md:394)).  
    **Required change:** route return-stage changes through E28-owned authoring inputs and regeneration. Agree the history-port owner, exact signature, snapshot semantics and bounds before adapter implementation. Record these requests in the required request artifact and make their resolution explicit build prerequisites.

15. **[major] Sections 8, 12 and 15: several acceptance tests cannot prove their stated outcomes.**

Align registered markers, test locations and gate selectors, and fail when expected scenarios are not collected. Add the missing fault cases above, enforce domain/application branch coverage and required mutation checks, and verify rendered demo exclusion rather than only absence of one endpoint call.
