VERDICT: CHANGES REQUESTED

1. **[blocker] Section 3.1 and 3.3: re-extraction can change an immutable citation’s text.** [E10:85](docs/tdd/E10.md:85) derives document identity from captured bytes and passage identity from that document ID plus offsets. Line 256 permits re-extraction with a new text hash. Two extractions of the same PDF can therefore produce different text at the same offsets under the same passage ID. Package `backlog.json:432` requires: “Every approved citation resolves to immutable source span and license record.” **Required change:** introduce immutable extraction identity, including extracted-text hash and extraction version; incorporate it into passage identity and bind reviews to it. Preserve previous extractions. Add a regression test where corrected extraction changes text without changing offsets.

2. **[blocker] Sections 3.7 and 5.4: the bundle cannot satisfy its own verification contract on a fresh laptop.** [E10:424](docs/tdd/E10.md:424) requires every passage to resolve to a stored blob and verifiable extracted-text slice. The exhaustive bundle format at lines 725 to 731 contains neither document-version records nor source/extraction blobs. Package `LLM-ARCHITECTURE.md:80` requires preserving “immutable originals and SHA-256 hashes.” **Required change:** specify the artifacts, provenance records and hashes transported with a release so installation and verification require neither the workbench store nor the network. Preserve span and license references for historical passages too. Test installation and verification on an empty, disconnected hub.

3. **[blocker] Sections 4.1 and 6: passage reads cannot enforce the pinned release and approved purpose.** [E10:474](docs/tdd/E10.md:474) gives `get_passage` only a passage ID, although section 4.3 says assessment callers pass a release ID. Section 6 resolves against the active release. `parent_section` also lacks purpose and applicability parameters. Package `CONTRACTS.md:166` says “Only allowed release and use”; line 248 defines rejection for evidence not approved “for this release and use.” **Required change:** separate historical inspection from approved retrieval. Specify release, purpose and applicability checks for passage reads and context expansion, including the exact filter semantics. Expansion must not expose adjacent unapproved text or exceed licensed content. Request any necessary HTTP selectors in section 14. Test activation during assessment and reads under the wrong purpose.

4. **[blocker] Sections 3.3 to 3.6: approval and supersession are stored at the wrong granularity.** [E10:241](docs/tdd/E10.md:241) gives a document one review state; line 254 supersedes it when a later version is approved for the same use. A version approved for both `risk_context` and `patient_instruction` cannot represent supersession of only one purpose. The transition table also has no route to add clinical approval after risk-context approval. Package `CONTRACTS.md:129` explicitly states: “Approval belongs to a version and purpose.” **Required change:** model approval, withdrawal and supersession per immutable target and purpose, with a defined aggregate display state. Add transitions and property tests for mixed-purpose approvals, later clinical review and purpose-specific withdrawal.

5. **[blocker] Sections 3.3, 4.1 and 12: imported captures cannot reach approval through the specified workflow.** [E10:683](docs/tdd/E10.md:683) initializes every capture as `unassessed`; T-E10-08 refuses extraction of unassessed versions. Completeness is set at the technical-check transition, which requires extraction first. No port supplies a preceding completeness assessment. Package `CONTRACTS.md:127` specifies the progression through captured, extracted and technically checked states. **Required change:** define an audited, revision-checked completeness-assessment command before extraction, its authorized actor and its evidence requirements. Reconcile this with E19’s workflow and test the entire capture-to-release path, including summary-only rejection.

6. **[major] Sections 3.3 and 5.1: URL deduplication loses valid source IDs.** [E10:218](docs/tdd/E10.md:218) permits one `source_id` per catalog item, while line 653 makes normalized URL unique. Package `NASA-SOURCES.md:50` states: “A document used in more than one of them has one ID in each.” Its lines 54 and 65 identify the same URLs as `EV01`/`RT03` and `EV12`/`RT10`/`RS51`. **Required change:** introduce a source-ID-to-document relation that preserves every declaration while deduplicating document content. Define retrieval and supersession across these aliases. Test all IDs resolving to the same document without replacement or duplicate independent evidence.

7. **[blocker] Sections 4.3, 5.3 and 12: rollback and pruning break citation history.** [E10:756](docs/tdd/E10.md:756) reads history only from the active release. After activating B and rolling back to immutable A, citations introduced in B disappear from that lookup. T-E10-16 also claims a pruned A can be resolved through B’s history, but the history table lacks A’s complete passage metadata and release membership. Package `PRD.md:497` requires superseded guidance to remain “discoverable in history”; `CONTRACTS.md:422` prohibits erasing lineage. **Required change:** preserve immutable passage artifacts and release membership independently of the active pointer, with reference-aware retention. Never substitute B’s interpretation for a pinned A read. Test A → B → rollback A, branching releases, pruning and restoration.

8. **[major] Sections 4.1 and 4.3: locking does not provide the promised concurrency or retry semantics.** [E10:511](docs/tdd/E10.md:511) checks the target release revision; rollback accepts no expected revision. Two clients activating different verified targets can both succeed sequentially because the second target’s revision did not change. A release ID alone also cannot distinguish a retried command from a later intentional action. Package `CONTRACTS.md:203` requires optimistic concurrency, and line 210 requires the same command key and body to return the first result. **Required change:** compare an expected active-release generation, persist command keys and payload hashes, and apply these rules to CLI and E19 calls. Test different-target races, rollback races and delayed retries after another activation.

9. **[major] Sections 4.3, 5.1 and 9: filesystem durability and disk-full recovery are unspecified.** [E10:617](docs/tdd/E10.md:617) specifies `O_EXCL` blob writes, but no temporary-file publication, flush ordering or repair of a partially written hash path. The `VERIFIED` marker and database state also have no coordinated recovery protocol. Startup rejection makes an interrupted release terminal, while installation of the same release simply returns its existing record. Package `CONTRACTS.md:433` requires restore tests covering evidence-release consistency; `AGENTS.md:101` explicitly requires disk-full and clock-jump fault injection. **Required change:** define durable file publication, database/filesystem reconciliation, typed storage failures and safe retry of interrupted installs. Test failures at every publication boundary, disk exhaustion, corrupt registry/configuration and clock jumps. Ordering must follow committed lineage, not wall-clock comparisons.

10. **[major] Sections 5.4, 5.5, 8 and 11: operational bounds are incomplete and several are hardcoded.** [E10:729](docs/tdd/E10.md:729) bounds compressed bundle size, line count and passage length, but not decompressed bytes, other JSON records, nesting, vector dimensions or accumulated history. The installer subprocess has a performance target but no enforced deadline. Query limits, retry delays, batch sizes and reader-cache limits have no named configuration fields. Package `CONTRACTS.md:1113` says: “when a module needs a word or a number that no document holds, add it to a document and its schema.” **Required change:** define a versioned operational-policy schema with provenance, validated limits and startup checks. Specify streaming parsing, archive-member type restrictions, finite vector validation, subprocess cancellation and bounded resource use. Add parser property tests and oversized/compressed-input fault tests.

11. **[major] Sections 3.5, 3.6 and 4: review evidence and discrepancies have no complete inter-module interface.** [E10:407](docs/tdd/E10.md:407) says discrepancies come from E19 ClaimReviews, but `ReleaseBuilderPort.build` accepts only approvals, and `ApprovalInput` carries no discrepancy records. There is also no port for validating the authoritative review chain against the exact reviewed extraction. Package `VALIDATION.md:44` requires the discrepancy to be “visible for review”; the charter prohibits reading another module’s tables. **Required change:** specify a typed, immutable review export or application port covering review identities, reviewed hashes, attestations, claim relations and discrepancies. Define how S0 curation supplies the same evidence. Test rejection of mismatched reviews and delivery of a discrepancy to E19’s review surface.

12. **[major] Sections 4.1 and 9: degraded states cannot be represented by the declared signatures.** [E10:477](docs/tdd/E10.md:477) returns plain tuples from searches, while line 836 promises empty results carrying `no_active_release`. Missing FTS is described as disabled and logged, without a typed result. `is_active -> bool` cannot distinguish an invalid condition from an unavailable registry, although loader checks must report that distinction. Package `backlog.json:502` requires “no-result explicit”; `PRD.md:621` requires failures to have visible outcomes. **Required change:** define result unions or typed errors for unavailable release, unavailable index, corrupt registry and genuine empty results, plus their E01/E12/API mappings. Add separate tests for each state and verify safety callers still return promptly.

13. **[major] Sections 2 and 3.4: the pathway handoff cannot support the downstream epic.** [E10:314](docs/tdd/E10.md:314) supplies an indicative assessment card, two review states and supporting passages of “any use.” It supplies no executable steps, equipment/operator requirements, applicability or versioned decision rules. Package `backlog.json:460` requires E11 pathway execution to check equipment and operator and keep drafts visibly simulation-only. Local `docs/tdd/E11.md:677` already requests the missing `PathwayVersion` contract. **Required change:** resolve that seam explicitly in section 14, assign ownership of its schema and content, and distinguish planning cards from approved executable pathways. Add a shared contract fixture and tests that unreviewed cards cannot authorize LIVE guidance.

14. **[major] Section 13: ownership overlaps E19.** [E10:977](docs/tdd/E10.md:977) claims all of `knowledge/policy/**` and `knowledge/schemas/**`. `docs/tdd/E19.md:625` claims files inside both trees, including `workbench-policy.json`, `workbench-policy.schema.json`, `review-status.schema.json` and `coverage.schema.json`. Template section 13 requires ownership “disjoint from every other epic.” **Required change:** replace these broad claims with exact E10 filenames or disjoint subdirectories, explicitly excluding E19’s files. Record shared schema changes through the request process.

15. **[major] Section 10: query hashing does not establish private-content-safe logging.** [E10:874](docs/tdd/E10.md:874) logs an unsalted SHA-256 of each query. Clinical queries can contain private symptoms; predictable queries can be identified by hashing candidate phrases and matching the log. The canary tests inspect stores and indexes, not this derived log content. Package `CONTRACTS.md:72` limits ordinary logs to references and necessary state changes rather than private symptoms; `VALIDATION.md:46` includes routine logs in V26. **Required change:** omit query-derived fingerprints from routine logs. Define any separately authorized diagnostic logging with access and retention controls, and extend privacy tests to log output.
