VERDICT: CHANGES REQUESTED

The package requires a different rendered release to return `409 CONFIG_VERSION_MISMATCH`. [CONTRACTS:214](docs/product/CONTRACTS.md:214) Keeping a question and choice ID while changing their meaning would silently reinterpret an answer. Removing a red flag also makes an episode's pinned completion requirement unanswerable. Require version checks, define historical correction and pinned red-flag behavior, and use the historical document reader specified in [SYSTEM:329](docs/SYSTEM.md:329). Any red-flag exception needs an explicit contract request and must preserve the rendered version. Test changed wording, removed questions, rollback and delayed submissions.

2. **[blocker] Sections 4.1, 9 and 12: downstream evaluator failures can prevent valid answer capture.** [E04:277](docs/tdd/E04.md:277) runs E11, E15 and E22 reactions inside the answer transaction without specifying failure isolation. [SYSTEM:967](docs/SYSTEM.md:967) now requires evaluator savepoints, `evaluation_pending`, durable reevaluation and unchanged existing safety state. This directly addresses audit finding 9. Adopt that protocol and distinguish domain rejection, evaluator failure and storage failure. Also define dispatch ordering: synchronous subscribers currently run before E04 inserts the chain row or records the new route. Test a permanently failing evaluator, disk full, commit failure and restart, including the visible unsaved or evaluation-unavailable state.

3. **[major] Sections 4.1, 4.5, 7 and 9: disconnected command recovery is neither durable nor complete.** E04 keeps submissions in memory and clears them on session lock. [E04:371](docs/tdd/E04.md:371), [E04:474](docs/tdd/E04.md:474) Deployment instead requires encrypted, person-partitioned queued commands that are “never discarded.” [DEPLOYMENT:365](docs/DEPLOYMENT.md:365) The package's “Keys are kept 24 hours” requirement is itself insufficient for prolonged disconnection, as audit finding 9 explains. [CONTRACTS:210](docs/product/CONTRACTS.md:210) Use the shared command journal and mission-lifetime ledger, with the post-cache response documented through R-SYS-8. Specify correlation between an offline concern, its answers and its help session before the episode has a server ID. Test browser restart, lock, changed user, lost response and replay after several weeks.

4. **[major] Sections 1, 3.6 and 12: clock skew blocks legitimate clinical recording.** The invariant rejects every answer or onset later than hub receipt time. [E04:240](docs/tdd/E04.md:240) A tablet clock ahead of the hub, or a backward hub correction, therefore prevents recording an otherwise valid urgent answer. The package says “Unknown time zone, device drift and clock corrections are recorded.” [CONTRACTS:9](docs/product/CONTRACTS.md:9) Define preservation of original timestamps, clock provenance and visibly uncertain timing, without clamping or silently replacing times. Use one `uow.now` per command and commit sequence for ordering. Add forward and backward clock-jump tests, including queued red flags and approximate onset boundaries.

5. **[major] Sections 5.1 and 9: the chain cannot reliably be rebuilt or reconciled as specified.** Rebuilding by `received_at`, then answer ID, can place a correction before its predecessor after a clock regression. [E04:412](docs/tdd/E04.md:412) Concurrent corrections from disconnected nodes also violate the unique successor constraint. Deployment's blanket answer rule, “Union; never a conflict,” is itself incomplete for supersession. [DEPLOYMENT:269](docs/DEPLOYMENT.md:269) Define causal rebuild order, missing-parent handling, atomic replacement and preservation of competing branches. Enforce episode home-node ownership and request an explicit answer-correction conflict rule. Test clock regression, child-before-parent delivery, duplicate import and two disconnected corrections without discarding either accepted record.

[E15:308](docs/tdd/E15.md:308) The package grants that role access to “Explicitly shared clinical records.” [PRD:146](docs/product/PRD.md:146) Concern text can reveal sensitive information even when individual answers are filtered. Require a purpose-specific grant for ordinary reads and a separately authorized, scoped, labeled and audited emergency-access path. Reconcile E02, E15 and SYSTEM's broader role wording. Test HTTP responses, conflict responses, events and caches with an unconsented officer session.
