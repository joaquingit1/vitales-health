## New findings

1. **[major] (introduced by the revision) Sections 5.2 and 5.3, R-E23-15: the demo channels exist only once E21
   accepts a request, and nothing supplies them meanwhile.**
   The demo registry now lives only in E21's fixture (`fixtures/demo-mara-fd19/sensors/sensor-channels.json`, lines 628
   to 629). The hub loads channels only from it in the demo profile. Until R-E23-15 is accepted and E21 builds the
   file, "with none, there are no channels and every card shows `no_reading`" (lines 627 to 628). Readings from E21's
   interim feeder then go to unknown channels and are rejected at their index (step 2, lines 352 to 353). R-E23-15's
   interim names only "E21's interim feeder" (requests lines 192 to 193), not a registry. Several things then cannot
   run during the interim:
   - the E23-02 acceptance ("The Rodent Research-1 CO2 and RadLab dose-rate series feed their channels labeled
     Replay");
   - T-E23-029, T-E23-061 and T-E23-084;
   - build step 6's walking skeleton W1.5 (line 1055, SYSTEM.md 8.8, checkpoint CP2).

   AGENTS.md:232 says an interim never switches off an acceptance criterion.
   **Required change:** give R-E23-15 an interim that keeps the demo channels. For example, E23 ships a demo registry
   and feed file under its own test or `eval/scenarios/e23/` path, loaded only by the demo profile, until E21 adopts
   them. Alternatively, make E21's acceptance a build prerequisite and say so in section 15. Either way, state which
   path T-E23-029 and T-E23-061 use.

2. **[minor] (introduced by the revision) Section 3.3 step 4: channels outside the new environment get the
   `activated_at` reference and raise a false "sensor quiet".**
   `on_activated` "sets the freshness reference of every channel that had readings to `activated_at`" (line 212),
   including channels whose `environment_ids` exclude the new environment. After a switch to `lunar_surface`, the
   station replay channel `ch_co2_cabin_replay` (`environment_ids` `[station_leo]`) goes stale once its replay stops.
   Its sensor type `co2` is in the lunar profile, and E24 raises `sensor_quiet` for a sensor type of the environment
   (E24.md:166). The result is a Moon base "sensor quiet" warning that names a station channel no card shows, which
   cuts against D18 ("No station reading ... appears as a current Moon base value").
   **Required change:** apply the `activated_at` reference, and publish freshness transitions, only for channels whose
   `environment_ids` include the active environment. Add the case to T-E23-079.

3. **[minor] (introduced by the revision) Section 3.3 step 4: the `activated_at` reference schedules no deadline.**
   The primary deadline is scheduled only "in the ingest unit of work, for each channel whose reference advanced"
   (lines 237 to 238). `on_activated` sets references (line 212) but schedules nothing, so the stale transition for
   finding r2 3 relies on the backup sweep alone, up to `sensors.freshness_sweep_s` late.
   **Required change:** have `on_activated` call `uow.schedule` for each reference it sets. Assert in T-E23-079 that the
   deadline, not the sweep, records the transition.

4. **[minor] (introduced by the revision) Section 5.2: the health poll shares the safety sweep's task, reaches only
   loopback adapters, and is ambiguous for REPLAY.**
   - The poll runs "in the same background task as the sweep" (line 612). With several adapters, each poll waits up to
     `sensors.adapter_poll_timeout_s`, and the waits add to the sweep tick of the critical path backup.
   - Every adapter names a "loopback `health_url`" (lines 609, 626 to 627). But T5 puts the LIVE adapter on a separate
     integration node that pushes to the site hub (DEPLOYMENT.md 3.6), so once R-E23-2 lands, a LIVE feed would always
     be `unknown` and its warnings could never clear.
   - Line 153 makes REPLAY `trusted` from the reading's `time_basis`, while line 155 makes any adapter with no endpoint
     `unknown`. R-E23-15 (requests line 191) reads this as applying to E21's replay feeder.

   **Required change:** run the poll in its own task, or bound the total poll time below the sweep period. Allow a
   non-loopback `health_url` with the same timeout. Say whether REPLAY `clock_state` depends on the poll.
