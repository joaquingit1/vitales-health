VERDICT: CHANGES REQUESTED

1. **[blocker] Sections 3.6 and 4.3: general help-session readability is mistaken for helper membership.** [E02:447](docs/tdd/E02.md:447) consumes `readable_by` as a membership fact, but [E26:234](docs/tdd/E26.md:234) defines it as permission to read the session, which every crew and station session has. E02 row 10 then grants P2 access. Replace this with a fact containing the actual subject, open state and authenticated person’s membership, read in the caller’s snapshot. Verify the subject matches the requested data. Test an uninvolved crewmate, a station session, another subject’s help session and concurrent closure.

2. **[blocker] Section 3.6: the decision table does not enforce consent validity, fields and purpose consistently.** [E02:215](docs/tdd/E02.md:215) allows a task operator without checking `consented_scopes`; an expired grant can therefore leave an accepted task readable. Rows 2 and 7 authorize sharing without applying `ConsentGrant.fields`, and rows 10 to 12 are not restricted to particular purposes. Require current consent wherever the relationship depends on it, intersect the returned fields with the grant and permitted projection, and explicitly enumerate authorized purposes. Add expiry, restricted-field and unauthorized-purpose tests.

3. **[blocker] Sections 5.3 and 7: idle lock does not protect an unattended, disconnected screen.** [E02:633](docs/tdd/E02.md:633) explicitly waits for a 401 until a proposed session field exists. With the hub unreachable, private content remains displayed indefinitely. Moreover, [E02:573](docs/tdd/E02.md:573) measures activity by requests, so background refreshes can keep an unattended session alive. Specify a local lock driven by human activity, with a configured deadline available before displaying private data. Integrate E03’s request epochs and draft clearing. Test disconnection, background polling, suspended tabs and late responses.

4. **[blocker] Section 3.2: the clock-regression formula extends sessions.** [E02:102](docs/tdd/E02.md:102) claims `max(now, last_seen_at)` prevents extension. With last activity at 10:00, expiry at 10:05 and a one-hour backward jump, six real minutes later the comparison still uses 10:00 and admits the session. This directly contradicts INV-E02-15. Use injected monotonic deadlines within the process epoch, with a conservative restart policy, or end affected sessions on regression. Test elapsed time independently of wall time and ensure correction cannot revive expired grants.

5. **[blocker] Sections 4.2 and 5.3: CLI revocation does not reliably stop existing SSE streams.** [E02:337](docs/tdd/E02.md:337) makes SSE liveness an in-memory lookup, while [E02:572](docs/tdd/E02.md:572) refreshes revocations only on HTTP requests. A separate CLI process cannot invoke the hub’s in-memory callbacks. An established stream can continue delivering private events after revocation. Specify authoritative epoch revalidation before delivery and heartbeat, plus cache and keyring invalidation across processes. Test CLI revocation with no subsequent HTTP request.

6. **[blocker] Sections 3.8 and 6.2: adapter binding lacks request-assignment authorization.** [E02:238](docs/tdd/E02.md:238) derives the subject from the named request but never requires that request to belong to the authenticated adapter. The path check at line 615 cannot protect `recordAttempt`, whose route contains only `request_id` ([OpenAPI:4933](docs/product/api/openapi.yaml:4933)). Require E05 to attest the adapter’s assignment, device/capability and acquisition context before binding or accepting results. Test one trusted adapter submitting another adapter’s request.

7. **[blocker] Section 3.8: manual record entry for an incapacitated crewmate depends on E05 and the subject’s consent.** [E02:237](docs/tdd/E02.md:237) permits another subject only through an accepted task and active grant. This contradicts [E01:644](docs/tdd/E01.md:644), which permits a medical officer to record directly, and defeats the required fallback when the subject cannot consent and E05 is absent. Reconcile the binding rule with the authorized onboard care path, preserving subject verification and audit. Test manual entry by the officer with the subject incapacitated and optional modules stopped.

8. **[blocker] Section 5.2: an old golden mirror can resurrect deleted private data.** [E02:556](docs/tdd/E02.md:556) updates removable media only when mounted and checks tombstones from the “newest available copy.” Delete data while the medium is absent, lose the laptop, then restore solely from that medium: both the old keys and the absence of deletion tombstones return. Define a recovery protocol that refuses private recovery when deletion-state freshness cannot be established, and an honest deletion acknowledgement state. Test this exact sequence and crashes before mirror refresh. Remove the unencrypted mirror interim at line 848.

9. **[blocker] Sections 3.5 and 5.2 to 5.4: credential changes and destructive key operations lack a recoverable transaction protocol.** Credentials and keys commit separately from sessions, revocation epochs and audit ([E02:550](docs/tdd/E02.md:550)). “Every CLI write runs … in a UnitOfWork” does not make those stores atomic. A crash can leave a changed credential without session revocation or an irreversible deletion without its audit. An in-flight Argon2 verification can also finish after credential replacement. Specify durable operation intents, ordering, recovery and credential-generation fencing before session issuance. Fault-test every commit boundary and concurrent sign-in/reset.

10. **[major] Sections 4.2 and 14.6: the journal cipher seam does not match E03.** [E03:380](docs/tdd/E03.md:380) requires `PrivateKeys.data_key()` and `DataKey.mac()` for the keyed command fingerprint. [E02:417](docs/tdd/E02.md:417) provides neither and describes replacing an obsolete `FieldCipher`. The designs also disagree on locked-key errors. Agree one interface covering encryption, keyed fingerprints, replay, destruction and recovery across the keystore, private store and hub. Update the actual consumer contract and test crash/retry integration against it.

11. **[major] Sections 3.6, 4.2 and 10: consented private-report sharing is internally contradictory.** Row 2 permits it, but [E02:711](docs/tdd/E02.md:711) says private reports are never shipped, and T-E02-026 rejects P3 for every destination. `PrivateCipher` also has only an owner-session decryption path. SYSTEM 8.3 explicitly permits consented report recipients and reports the owner sends. Define an owner-authorized, field-limited transfer and recipient read path, including revocation and delivery audit, while keeping the journal prohibited. Test both allowed sharing and denied sharing.

12. **[major] Sections 3.1, 4.1 and 6.1: authentication is incomplete for supported principal kinds.** [E02:91](docs/tdd/E02.md:91) permits multiple non-person principals per kind, but `SessionCreate` supplies no principal selector and the design budgets one Argon2 derivation. It never defines which credential record to verify. Adapter tokens also lack the session ID, expiry and sign-out semantics required by the two current-session operations. Define these cases explicitly, using one principal per kind as an interim or filing a selector change. Resolve whether and how the never-rostered `demo_operator` authenticates despite the off-roster rejection.

13. **[major] Section 3.3: the lockout is neither independently per person nor independently per client.** [E02:110](docs/tdd/E02.md:110) counts only `(principal_key, client_key)` pairs. Rotating clients bypasses the person limit; rotating principal IDs bypasses the client limit. DEPLOYMENT 5.3 requires both. Specify separate aggregate limits and bounded handling of unknown identities. Test distributed attempts, concurrent attempts, restart and clock regression.

14. **[major] Sections 5, 8 and 11: operational bounds and setting names are incomplete.** The implementation references `identity.session.activity_flush_seconds` and `identity.session.sweep_seconds`, but [E02:655](docs/tdd/E02.md:655) declares different keys. Similar mismatches affect sign-in and orphan-grace settings. Roster enumeration, arbitrary mission-day ranges, sign-in-counter cardinality, reconciliation and whole-keystore mirror work lack explicit limits and overflow behavior. Provide one exact settings inventory, admission and batch rules, and tests that exceed each bound while help remains responsive.

15. **[major] Sections 2, 4.2 and 13: several remaining shared interfaces cannot be wired as written.** E01 expects `require_roles(operation_id)` and `PersonNamespacePort`; E13 expects `ConsentQueries.purposes`; E22 requires roster `version()`; E31 requires `roster_index`. E02 supplies different names or omits those members ([E02:305](docs/tdd/E02.md:305), [E22:323](docs/tdd/E22.md:323), [E31:367](docs/tdd/E31.md:367)). E01 also uses an `observation` consent scope absent from E02. Settle exact signatures and semantics with the coordinator and consumers. Narrow `keystore-only-identity` to E02’s keystore files: forbidding all other modules from opening `keys/` conflicts with E01 backup encryption and E20 TLS/key management.

16. **[major] Section 14: none of E02’s requests is filed.** `docs/requests/E02.md` is absent; [E02:817](docs/tdd/E02.md:817) onwards contains proposals only inside the design. AGENTS rule 9 explicitly says those do not constitute requests. File each proposal with target, exact change, reason and safe interim. Obtain coordinator resolution for new shared mechanisms before treating them as settled interfaces; reference the filed requests from the TDD.

17. **[major] Sections 1, 8, 12 and 15: required traceability and review gates are missing.** There is no normative rule trace, acceptance matrix, dedicated time specification or activation-effects section. Running `.venv/bin/python -B scripts/design_lint.py docs/tdd/E02.md` returned exit 1 and confirmed these omissions and unfiled requests. Add the source-line rule trace and explicit mappings for all three work packages, R02/R20/R29 and the claimed V/D clauses, including ownership of remaining scenario clauses. Specify activation behavior for the UI configuration and settings actually consumed. Resolve applicable lint findings and rerun the gate.

18. **[major] Section 12: several declared tests contradict valid behavior.** [E02:753](docs/tdd/E02.md:753) demands denial for every list and ID-based operation, including legitimately shared resources. T-E02-007 excludes the owner’s `writeJournal` response although OpenAPI requires a `JournalEntry` containing text. T-E02-014 prohibits the initial token response. T-E02-011 expects station `recordObservation` to reach a 422 binding error, although its role gate must return 403. Replace these with operation-specific authorization expectations and explicit allowed-response exceptions. Preserve positive authorization tests alongside adversarial cases.

Package issues: none identified beyond already settled decisions.
