# E18 conformance pass

E18 had no prior review, so this note answers no comments. It lists the changes that bring `docs/tdd/E18.md` in line
with `docs/SYSTEM.md`, COORDINATOR-DECISIONS Part A and `docs/tdd/TEMPLATE.md`, by section. Requests are in
`docs/requests/E18.md`. `scripts/design_lint.py docs/tdd/E18.md` reports 0 errors. The design is 68,473 bytes; it was
69,062 bytes before this pass.

## Whole document

- Restructured to TEMPLATE.md: added 1.1 rule trace, 3.1 time, 8.1 activation effects, 10.1 failure and edge cases,
  the 11 settings table and the 12.1 acceptance matrix. Section 7 reads "None".
- Removed the restated package and SYSTEM.md text. The design now cites sections instead: Clock 5.2, IdFactory 5.1,
  Quantity 5.4, ErrorEnvelope 5.5, events 5.7, idempotency 5.8 and 8.6, settings shape 5.11, workspace members 6.2,
  reference machines 8.7.
- Every request moved to `docs/requests/E18.md` (R-E18-1 to R-E18-11, Q-E18-1, Q-E18-2). Section 14 only lists them.

## By section

- **1 Scope:** removed the D IDs that E21 owns (D01, D44); E18 delivers no D scenario. States that E18 owns no
  CONTRACTS section; the CONTRACTS rules it implements are traced in 1.1.
- **1.1:** one row per rule of CONTRACTS.md, PRD.md, VALIDATION.md, LLM-ARCHITECTURE.md and AGENTS.md that E18
  implements, plus COORDINATOR-DECISIONS Q19 and D2. Each row names its section and test.
- **2 Seams:** split into provided and consumed tables.
  - `GateVerdict` carries `release_id`, with one verdict per release (answers E17 request 4).
  - The run manifest carries the fields E19 asked for (answers E19 request 8; path in R-E18-9).
  - The freeze library ownership answers E21 request 16 (R-E18-4).
  - Timeouts on consumed ports are `Quantity` (R-E18-8).
  - The `llama-server` endpoint is written as "`/v1/chat/completions` (POST)" because it is not a hub endpoint.
- **3.1 Time (new):**
  - durations are monotonic per `process_epoch`;
  - ordering is by `seq`, and an event gap or `CURSOR_EXPIRED` gives `harness_error(event_gap)`;
  - no mission time or freshness is computed (D3);
  - every timer is relative.
- **3.2:**
  - `case_id` and `canary` come from `IdFactory`;
  - simulated values are `Quantity`;
  - new `ConfigPrecondition` (`requires`) and `not_run(config_precondition)` for Q19;
  - labels are golden cases, with D2 enforced through `label_constraints`.
- **3.5:**
  - `run_id = IdFactory.derived("benchrun", ...)`;
  - the manifest adds `registry_version` and `bench_documents_sha256`;
  - the abort reasons add a hub storage fault.
- **3.6:** `ModelReleaseRef` is a projection of E17's release file. It carries `weights.lineage`, `tool_call_mode` and
  `evaluated_with`, and the identity check uses `GET /props`.
- **3.7:** `reviewer_qualification` is `engineering` until a clinician grades (Q1).
- **3.8:** INV-E18-12 restricts a gate verdict to one `release_id`.
- **4.1, 4.2:**
  - failure codes are snake case reasons, and no hub `ErrorCode` is defined (D5);
  - a crash table per command (unit of work);
  - a storage error stops at once with exit 6 and is never recorded as a result.
- **4.4:** port timeouts are `Quantity`.
- **4.7:** one sequence diagram. The failure paths refer to 4.1 and 4.2.
- **5.6:**
  - an Idempotency-Key is reused only for the same operation, path and body;
  - `DUPLICATE_COMMAND` with `current_state` counts as accepted;
  - `INTERNAL_ERROR` gives `harness_error`;
  - a hub storage cause gives `aborted(hub_storage)`.
- **6.1:** calls are listed by `operationId`, with error handling by code.
- **6.2:** CLI failures use the RFC 9457 view of SYSTEM.md 5.5 (D5).
- **6.3:** `case_results.public.jsonl` is renamed `case_results.jsonl`, the name VALIDATION.md:245 requires; E21's seam
  row still names the old file (R-E18-11). The run manifest
  `status` maps to E19's values.
- **8:**
  - the evaluation documents moved under `eval/bench/config/` with schemas and provenance (R-E18-2);
  - Q19 paragraph: no case assumes a supply low default;
  - the configuration edit test is T-E18-17.
- **8.1 (new):** the effect of each document change on runs. None of them touches a crew hub.
- **9:** cites reference machines R1 and R2, and the capsule tablet as "not measured" (SYSTEM.md 8.7).
- **10.1 (new):** one row per failure case of AGENTS.md section 6, each with a test.
- **11:** every bound is a named `bench.*` setting in the hub settings shape (D7). Because E18 runs outside a hub, the
  interim is `eval/bench/config/bench-settings.json` (R-E18-1).
- **12, 12.1:**
  - tests T-E18-32 to T-E18-34 added (idempotency, clock, activation drift);
  - a markers column (`e18`, `v33`, `v34`);
  - the matrix covers E18-01 to E18-03, R22, R23, R30, R46, V33, V34, V22, V23, V25, V26 and V63.
- **13:** E18 claims only `eval/bench/**`, `eval/vault/**`, `eval/scenarios/E18/**` and its two documents. The
  `eval/harness` conflict is R-E18-4.
- **15:** gate commands use `uv run --project eval/bench` and `pytest -m e18`.
