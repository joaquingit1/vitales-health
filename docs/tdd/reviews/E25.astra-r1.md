VERDICT: CHANGES REQUESTED

1. **[blocker] Sections 2, 4.1 and 10: routine failures can prevent recording a warning or reading.** UC-T9 and H11 roll back the producer when E25 fails. Retrying cannot recover from a persistent deterministic fault. This repeats audit finding 9. [CONTRACTS.md:1108](docs/product/CONTRACTS.md:1108) requires atomic state, audit and outbox writes, but does not require optional downstream evaluation to veto input capture. **Required change:** agree with E01 and E24 on durable input capture, pending evaluation and visible degraded status. Preserve existing warnings, retry evaluation with bounded processing, and test a permanently failing routine handler.

2. **[blocker] Sections 3.4, 3.14 and 4.2: an assistant recheck can postpone the normal schedule.** [E25:195](docs/tdd/E25.md:195) calculates the next periodic task from the latest ended occurrence, regardless of cause. A weekly task completed on day 14 is due on day 21; completing an assistant recheck on day 20 moves it to day 27. This violates [PRD.md:260](docs/product/PRD.md:260): the assistant “never removes, loosens or postpones a task.” The generic `warning_raised` binding path also lacks a guard against assistant warnings starting cadence overrides. **Required change:** prevent assistant occurrences from postponing existing obligations, reject indirect assistant cadence changes in the domain, and test both paths.

3. **[blocker] Sections 3.6 and 3.7: suppression can produce an invalid window or release a task too early.** [E25:242](docs/tdd/E25.md:242) sets `suppressed_since = max(due_from, overlay start)`, then adds `overlay end - suppressed_since`. For a 13:00 to 15:00 task and sleep ending at 08:00, the result is a 13:00 to 10:00 window. A single stored overlay also cannot correctly handle overlapping suppressing overlays. [CONTRACTS.md:623](docs/product/CONTRACTS.md:623) says nothing routine is due while a suppressing overlay is active. **Required change:** calculate nonnegative held duration over the union of applicable intervals, release only after all suppressing overlays end, and test early-ending, overlapping and reordered overlays.

4. **[major] Sections 3.7 and 3.10: open tasks disappear when their windows cross midnight.** Projection selects today's occurrences or historical final occurrences, omitting older open ones ([E25:370](docs/tdd/E25.md:370)). This affects overnight suppression and ordinary pre-walk tasks: the configured [1,440-minute pre-EVA window](docs/product/api/examples/config/routine-rules.example.json:83) starts the previous day. It also contradicts E25's statement that only suppression can cross midnight. **Required change:** define cross-day window semantics and include every still-open obligation in the actionable projection. Specify how it interacts with the next cadence occurrence, and test a next-morning walk and overnight sleep.

5. **[blocker] Sections 3.8, 4.3 and 10: origin isolation is asserted but not enforced by the specified algorithm.** Audience resolution uses the mission roster; nothing explicitly rejects a REPLAY warning against a LIVE roster. Several `TriggerInput` variants omit origin entirely ([E25:297](docs/tdd/E25.md:297)). T-E25-029 tests a SIM roster only. [CONTRACTS.md:421](docs/product/CONTRACTS.md:421) requires that no historical cabin series become current exposure without an explicit actual association. **Required change:** specify domain checks for mission, subject namespace and origin on every trigger, completion and replicated action. Test REPLAY and SIM inputs beside LIVE roster members, and preserve source time and origin in every resulting presentation.

6. **[major] Section 1, DE25-10: “everyone in location” is incorrectly implemented as everyone not on EVA.** [E25:58](docs/tdd/E25.md:58) ignores the warning's location even though the package provides [`CrewMember.location`](docs/product/api/schemas/crew-member.schema.json:26). [D20](docs/product/VALIDATION.md:175) specifies “everyone in the area.” A person in another compartment or rover is not established as exposed by being indoors. **Required change:** define location and occupancy resolution at the trigger instant, including unknown occupancy and movement between sites. Freeze the resolved audience and test two occupied locations. This addresses audit finding 8.

7. **[blocker] Sections 3.12, 8 and 10: a draft notice substitutes for clinical eligibility.** Every task's instructions are served in LIVE operation; R-E25-3 adds review metadata but no enforcement. [PRD.md:620](docs/product/PRD.md:620) requires: “Every displayed clinical recommendation has an approved passage or a fixed ‘not supported’ state.” [E25-03's clinical dependency](docs/product/backlog.json:1106) also requires reviewed content and trained operators where applicable. **Required change:** request and use shared eligibility rules tied to the exact content version, purpose, environment and required capabilities. Keep reminders and record entry available, but prevent unapproved instructions from becoming operational guidance. Add eligibility and independently reviewed content tests, addressing audit findings 4 and 17.

8. **[blocker] Section 3.8: configuration removal is treated as evidence that a hazard ended.** [E25:343](docs/tdd/E25.md:343) ends an override on any clear reason except `superseded`, including `config_changed`. The package explicitly clears “a warning whose definition is gone” on activation ([CONTRACTS.md:521](docs/product/CONTRACTS.md:521)). This is an unsafe upstream requirement: deleting a definition can end monitoring while its sensor is stale and the hazard unresolved. **Required change:** request explicit migration semantics that preserve unresolved obligations until fresh clearing evidence or authorized disposition exists. Test definition removal and incompatible rule changes while evidence is stale. Audit finding 3 remains applicable even though E24 now preserves warnings across text-only edits.

9. **[blocker] Sections 3.8, 3.9 and 4.3: repeat questions can be delayed, collapsed or terminated without being answered.** Attachments target the next open occurrence, so an alert after today's completed daily check can wait until tomorrow. Submission or abandonment finalizes attachments even when optional questions were unanswered. Generic coalescing can absorb a two-hour repeat into the original all-day occurrence. [CONTRACTS.md:869](docs/product/CONTRACTS.md:869) says `repeat_after_minutes` “asks again”; [D16](docs/product/VALIDATION.md:171) requires questions now and two hours later. **Required change:** define durable question instances, answer association, repeat deadlines and explicit unanswered outcomes. Parent-check submission must not satisfy them. Test late alerts, partial answers, abandonment, restart and repeats crossing midnight.

10. **[major] Sections 3.4, 3.5 and 8: executable cadence semantics do not represent the authored schedule.** The blood-pressure trigger says “measure now, then daily for 3 days” but has `word: as_needed` ([routine-schedule.json:376](docs/product/routine-schedule.json:376)); E25 creates only one occurrence. The sourced reaction-test cadence requires morning and evening tests ([routine-schedule.json:911](docs/product/routine-schedule.json:911)), while E25 generates one periodic occurrence. **Required change:** inventory these structured-data gaps across all items and request explicit phases and within-day slots. Do not parse clinical prose or silently reduce its meaning. Add independent expected schedules for these examples and resolve the inconsistent post-storm schedules in USE-CASES UC03 and the routine configuration.

11. **[major] Sections 3.11 and 12: the default miss policy cannot satisfy the weekly-task scenario.** The selected policy requires two misses within seven mission days, but ordinary weekly misses are seven days apart. Days 14 and 21 cannot both fall in the seven mission days ending on day 21. T-E25-011 nevertheless assumes this case. [V67](docs/product/VALIDATION.md:87) explicitly requires repeated weekly misses to trigger the question. **Required change:** choose a documented policy that accommodates the cadence, with source or team-decision provenance, and test actual calendar progression. Also distinguish a question displayed to the person from one merely attached to an abandoned check before consuming its once-only allowance.

12. **[major] Sections 2, 4.2, 4.3 and 7: the E03 integration contract disagrees with its consumer.** E03 specifies [`DailyCheckQuestionSource.added_questions`](docs/tdd/E03.md:299), `RoutineTodayPort`, and submission events without `added_question_ids`; E25 supplies different ports and reads that absent event field. E03 expects `ReactionTestRecorded` to complete a routine occurrence, but E25 does not consume it. E25 also requires a `taskRegion` prop absent from [E03's BodyFigure interface](docs/tdd/E03.md:504). **Required change:** agree exact signatures, event payloads, transaction participation, completion behavior and UI slots with the owners. Extend R-E25-16 to cover every discrepancy and add integration tests against the actual interfaces.

13. **[major] Sections 3.8 and 6: environment-triggered overrides have no valid source representation.** The binding schema permits [`on.kind: environment_activated`](docs/product/api/schemas/config-routine-rules.schema.json:376), and E25 creates an override for every trigger binding. However, [`RoutineOverride.source.kind`](docs/product/api/schemas/routine-override.schema.json:63) permits only `warning`, `mission_event`, `overlay`, `observation`, `answer` and `person`. Section 14 does not request the missing representation. **Required change:** propose the exact source schema and identity semantics, or an agreed existing-event mapping. Add a contract test for an environment-activated trigger producing a valid override.

14. **[major] Sections 3.12, 4.1 and 8: configuration activation has contradictory effects on open work.** Open occurrences retain their release, task steps always use the active release, and occurrence actions ignore `Config-Release` ([E25:439](docs/tdd/E25.md:439), [E25:514](docs/tdd/E25.md:514)). A person can therefore complete newly rendered instructions against an older occurrence without recording which instructions they followed. UC-T14 only recomputes projections, yet T-E25-025 expects an existing preferred time to change. **Required change:** specify atomic reconciliation of open occurrences, deadlines and revisions; preserve the guidance version actually acted upon; and honor configuration-dependent command validation. Test an activation between opening a task and completing it, including item removal.

15. **[major] Sections 3.8, 3.12 and 7: displayed cadence and provenance can misrepresent the active task.** A `note` replaces the cadence word, so a weekly conference becomes “Live,” and a daily vision check becomes “While CO2 stays above the limit.” Citation basis always comes from the base cadence, even when a team-default override governs. The To do component fetches personalized `RoutineTask` objects only once per release ([E25:898](docs/tdd/E25.md:898)), although overrides and environments change within that release. **Required change:** render frequency plus its qualifier, distinguish base and override provenance, and invalidate task projections on person, environment, occurrence and override changes. Test these changes without activating a new release.

16. **[major] Sections 4.1 and 5: idempotency ends before the supported outage can end.** E25 relies on a 24-hour response cache and generates random IDs for manual overrides. Replaying a creation after that cache expires and its previous override ends can create another override. This faithfully follows [CONTRACTS.md:210](docs/product/CONTRACTS.md:210), “Keys are kept 24 hours,” but repeats audit finding 9. [DEPLOYMENT.md:526](docs/DEPLOYMENT.md:526) now requires a durable command ledger in addition to that cache. **Required change:** define persistent logical command identity and replay results for every mutation, including ground-originated commands. Test response loss followed by retries after multiweek outages.

17. **[major] Sections 3.6, 5.1, 9 and 14: replication cannot obey the declared final-state invariant.** The domain rejects every transition from `missed`, and the SQL trigger rejects every update of a final row. Section 9 nevertheless says a valid remote completion beats a timer miss. [DEPLOYMENT.md:271](docs/DEPLOYMENT.md:271) now requires that exception. **Required change:** distinguish immutable recorded events from the reconciled occurrence projection and specify the merge algorithm, actor checks and history. Add disconnected-node tests for completion versus miss, completion versus skip and duplicate delivery. Replace provisional deployment statements with the published T0 to T7 mapping; SYSTEM.md was still absent at final inspection.

18. **[major] Sections 3.3, 4.3 and 5.3: time provenance and clock correction are insufficiently specified.** The mission-event handler reads `type` and `recorded_at`, while the package provides [`event_type`, `occurred_at` and `recorded_at`](docs/product/api/schemas/mission-event.schema.json:11). Using recording time moves delayed events into the wrong schedule. Occurrences and deadlines omit the governing clock version; only forward jumps have a test, and the fallback heartbeat is not defined in storage. **Required change:** preserve event time separately from receipt time, define clock-version and backward-correction behavior, and specify the lifecycle persistence contract. Test delayed events, backward jumps, corrections across midnight and restart during suppression.

19. **[major] Sections 3.13, 4.2 and 10: clinical access and delegated care are unresolved.** E25 grants every medical-officer session every personal override, but denies all other-person occurrence access and actions. [CONTRACTS.md:1085](docs/product/CONTRACTS.md:1085) grants manual-override management, not blanket access to all symptom-derived records. Meanwhile, an incapacitated owner has no specified route for authorized routine documentation. `barriers_since` also lacks an authorization or approved-export context. **Required change:** request precise patient, purpose, consent and delegated-care rules, preserving subject and acting person separately. Specify approved ground-summary inclusion and test unauthorized access, authorized assistance, revocation and shared-laptop session changes. This addresses audit finding 5.

20. **[major] Sections 1, 14 and 15: acknowledged requests leave required acceptance criteria undelivered.** Interim behavior replaces measurement entry with generic completion, omits quiet-sensor fallback tasks and automatic symptom tightening, and renders override ends as “Unknown.” These conflict with [UC02:121](docs/product/USE-CASES.md:121), [UC17:219](docs/product/USE-CASES.md:219), [V59](docs/product/VALIDATION.md:79), and E25-02's requirement for reason, source and end. **Required change:** make the necessary request resolutions explicit prerequisites of the affected work packages and gates. Record exact proposals in the required request artifact; no E25 request artifact was present. Do not exclude contradictory examples or weaken D17 without an approved package resolution.

21. **[major] Section 9: ground independence leaves private medical conferences without an executable path.** The authored routine requires a private flight-surgeon conference, selected sharing, recorded advice and store-and-forward messages ([ROUTINE.md:1112](docs/product/ROUTINE.md:1112)). E25 describes generic completion and ground catch-up logs, with no owner or interface for that private workflow. The pre-EVA description also says the flight surgeon “must clear you,” conflicting with its locally authorized steps. **Required change:** request reconciliation of these upstream requirements. Assign private asynchronous consultation and locally accepted advice to a concrete owner, distinguish queued communication from a completed consultation, and test prolonged disconnection without blocking immediate local care. This addresses audit finding 7.

22. **[blocker] Section 5.1: rollback destroys accepted records.** [E25:829](docs/tdd/E25.md:829) explicitly says rollback drops the module's tables. That deletes occurrences, outcomes, overrides and history, contrary to the charter's durable-record invariant and [DEPLOYMENT.md:469](docs/DEPLOYMENT.md:469): migrations within a mission are “additive only.” **Required change:** specify backward-compatible software rollback that retains all data and audit references. Test upgrade, accepted commands and rollback against the same database.

23. **[major] Sections 5.4 and 11: resource limits are not fixed bounds, and exhaustion behavior is incomplete.** `len(bindings)`, roster size and configuration-list length are not fixed bounds when the schemas impose no maxima. Repository methods return all active overrides or deadlines, and repeated inputs can grow those collections independently of the daily occurrence cap. Hitting the cap only logs a message ([E25:849](docs/tdd/E25.md:849)). **Required change:** define validated limits, bounded queries and batches, storage timeouts, retry limits and visible exhaustion states. Reserve or otherwise protect safety-related work from assistant-generated load. Test sustained input floods and help responsiveness with exhausted routine capacity.

24. **[major] Sections 4 and 6: the required error boundary is not buildable as written.** E25 names a few exceptions but lacks a complete typed-error mapping for storage, scheduler, configuration and rendering failures. It serves the package's `ErrorEnvelope`, while [BUILD-CHARTER.md:73](docs/BUILD-CHARTER.md:73) requires RFC 9457 problem details. The package schema rejects extra properties and documents `application/json`; section 14 does not resolve this conflict. **Required change:** request one shared wire-error decision and specify every E25 error's HTTP status, code, retryability, safe details and transaction outcome. Include disk-full, lock-timeout and commit-failure cases.

25. **[major] Sections 12 and 15: the acceptance evidence omits required cases and sometimes tests a different claim.** T-E25-045 is labeled V51 but tests CO2 and barrier questions; [V51](docs/product/VALIDATION.md:71) requires after-walk and radiation questions with unchanged completion requirements. There is no novice blood-pressure usability test for [R38](docs/product/PRD.md:514), nor explicit parser property tests, disk-full recovery or simultaneous two-client mutation tests. The redundancy table's manual-override backup also cannot start a bound trigger under the specified API. **Required change:** provide a requirement-to-test matrix that covers these exact scenarios and every corrected failure above. Exercise each claimed backup with its primary removed, add independently checked expected outcomes, and measure workload and interruption behavior as requested by audit finding 13.

Questions for the user: none.
