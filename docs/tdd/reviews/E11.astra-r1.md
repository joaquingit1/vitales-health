VERDICT: CHANGES REQUESTED

1. **[blocker] Sections 2, 4, 6, 13 and 14: E11 and E26 define incompatible integration contracts.** E11 treats `red_flag.ref_id` as an Answer ID and owns the urgent alias router ([E11:294](docs/tdd/E11.md:294), [E11:482](docs/tdd/E11.md:482)). E26 treats the reference as an Episode ID, also owns the alias, and assigns urgency consumption to E15 ([E26:70](docs/tdd/E26.md:70), [E26:461](docs/tdd/E26.md:461)). E11 also names `createHelpSession`, while the package says `operationId: openHelpSession` ([openapi.yaml:8464](api/openapi.yaml:8464)). **Required:** agree one endpoint owner, one reference meaning, and exact publication/subscription contracts for help opening and closure. Record the agreement through the request process and update the affected designs before parallel implementation.

2. **[blocker] Sections 4.1, 4.4 and 9: the claimed independent hub path never opens help.** `OnAnswerAccepted` only transitions urgency. The success sequence relies on a second client command to create the help session ([E11:293](docs/tdd/E11.md:293), [E11:386](docs/tdd/E11.md:386)). If the client disappears after the answer commits, the episode remains `active_response` with no help session; the inference gate then points to an empty session list. T-E11-022 claims a hub fallback that is not designed. The package requires: “Any yes opens ‘Someone needs help’” ([PRD.md:198](PRD.md:198)). **Required:** define a durable, idempotent server-side help-opening effect and reconciliation with client-created sessions. Test client loss between the two commands and restart before effect delivery.

3. **[blocker] Sections 4.1, 6 and 14: the interim disposition mechanism leaves valid urgent states permanently unclosable.** Until R-E11-1 is approved, disposition requires closing a linked help session with a note. Uncertainty and model review can create urgency without such a session. A crew member can also close the session first, leaving urgency unchanged and preventing a later officer from adding the disposition. The package says close permits “no further actions (`SESSION_CLOSED`)” ([CONTRACTS.md:918](CONTRACTS.md:918)); its close schema requires a disposition but not a note ([requests.schema.json:1338](api/schemas/requests.schema.json:1338)). **Required:** make an independently reachable urgency-disposition command a prerequisite for completing E11, with an owning UI and authorization contract. Test urgency without help, help closed by another person, and closure without a note.

4. **[blocker] Sections 4.1 and 5: help closure can dispose of urgency the officer never reviewed.** UC-U3 records disposition for linked open cycles without checking the episode or urgency revision ([E11:295](docs/tdd/E11.md:295)). A new urgent answer can change the episode while the help-session revision remains unchanged; an older close command can then dispose of the newly updated urgency. The package requires conflicting updates to return a conflict “rather than silently overwriting” ([CONTRACTS.md:203](CONTRACTS.md:203)). **Required:** bind disposition to an explicitly reviewed cycle and revision, checked atomically. Specify the conflict behavior and test both interleavings of a new urgent signal and an officer’s close command.

5. **[blocker] Sections 3.2, 4.1 and 10: cross-record authorization is missing at the urgency boundary.** Linking follows `ref_id`, but no invariant requires the referenced episode’s patient to equal the help subject. `AuthorizedOfficer` checks role and non-self status only; the model review command accepts an episode ID separately from its context ([E11:134](docs/tdd/E11.md:134), [E11:294](docs/tdd/E11.md:294)). Upstream scoping does not establish these relationships. The package explicitly says “Client/model-supplied IDs are not authorization” ([CONTRACTS.md:145](CONTRACTS.md:145)), and officer access is to explicitly shared records ([PRD.md:146](PRD.md:146)). **Required:** specify subject, mission, origin, authorized episode scope and current grant checks for every command and deferred link. Add adversarial cross-person reference, unauthorized officer and model-context mismatch tests.

6. **[major] Sections 4.1, 5 and 9: offline reconciliation lacks a usable correlation mechanism and loses delayed history.** The proposed session-before-answer path requires an Answer ID before the answer reaches the server ([E11:305](docs/tdd/E11.md:305)). `AnswerCreate` accepts no client-supplied ID and has `"additionalProperties": false` ([requests.schema.json:474](api/schemas/requests.schema.json:474)). Pending rows also expire after 24 hours and retain neither opening facts nor an early closure. The package’s 24-hour retention applies to idempotency keys, not clinical links ([CONTRACTS.md:210](CONTRACTS.md:210)). **Required:** define supported answer-first upload ordering or request a stable correlation field. Preserve unresolved linkage durably and reconcile opening, closure and answer history exactly once. Test outages exceeding 24 hours and open, close, answer arrival ordering.

7. **[blocker] Sections 3.5, 4 and 14: reviewed pathway execution is not specified.** `PathwayContext` contains environment, capabilities, consent and roster facts, but no clinical answers against which `DecisionRule.question_id` and `presence` can be evaluated. “Decision rules become `PathwayRule` signals” has no application command, triggering event, input snapshot or idempotency rule ([E11:234](docs/tdd/E11.md:234)). The only pathway use case is a read, consistent with the package tool’s `"effect": "read"` ([tool-catalog.json:147](tool-catalog.json:147)). **Required:** complete the proposed executable contract: typed clinical inputs, authored instruction references, rule matching and precedence, triggering commands, approval/applicability checks before effects, provenance and deduplication. Keep `get_pathway` read-only. Add an end-to-end test demonstrating E11-02 execution from accepted input.

8. **[major] Sections 3.5 and 14: evidence approval and supersession semantics do not match the supplying contract.** E11 checks `"patient_instructions"` ([E11:247](docs/tdd/E11.md:247)); the package’s allowed-use value is `"patient_instruction"` ([evidence-passage.schema.json:21](api/schemas/evidence-passage.schema.json:21)). E10 supplies `PathwayCard` through `EvidenceQueryPort.pathway_card`, not the proposed `PathwayVersion` interface ([E10:314](docs/tdd/E10.md:314), [E10:488](docs/tdd/E10.md:488)). E11 also says both that a replacement is evaluated and that a superseded pathway is refused, without defining the returned discrepancy. **Required:** agree the E10 mapping and canonical purpose vocabulary. Specify replacement selection within pinned releases, approval of referenced passages, discrepancy output, and behavior for withdrawn, missing or inapplicable replacements. Test those cases before enabling pathway effects.

9. **[blocker] Sections 3.6 and 8: the request gate has no contracted source for clinical applicability.** It assumes `applicable_environments` establishes clinical suitability and refers to capability overlay exclusions ([E11:264](docs/tdd/E11.md:264)). The package instead derives `applicable_environments` as “the environments whose kit holds a provider” ([CONTRACTS.md:1200](CONTRACTS.md:1200)). `Capability` has no overlay-exclusion field and rejects additional properties ([capability.schema.json:52](api/schemas/capability.schema.json:52)). Equipment presence therefore cannot enforce R07’s prohibition on standing tests in microgravity. **Required:** request a versioned clinical applicability document or field with its owner, schema, provenance and loader checks. Specify its mapping into `CapabilityFact` and prove a configuration edit changes the gate without code changes.

10. **[major] Sections 3.5, 3.6 and 4: unavailable capability states are misclassified, and operator checks are underspecified.** Every status other than `available` becomes `device_absent` ([E11:265](docs/tdd/E11.md:265)). The contract separately permits `not_applicable`, `operator_absent`, `context_inapplicable` and `adapter_down` ([capability.schema.json:59](api/schemas/capability.schema.json:59)). The design also does not define whether the actual assigned operator must qualify, what `operator_id=None` means, or which consent purpose and actions are checked. **Required:** provide a complete status/reason truth table and exact operator and consent predicates. Define manual-method fallback and the E05 revalidation point before acquisition. Test operator departure, consent revocation, adapter failure and an available manual alternative.

11. **[blocker] Sections 3.4 and 4.1: interruption is best effort, with no protection against stale model output.** Cancellation is an after-commit call whose failure is only logged ([E11:309](docs/tdd/E11.md:309)). A crash between commit and delivery loses it. A turn can also pass the gate immediately before urgency changes. The package requires a material new answer during inference to make output stale ([CONTRACTS.md:269](CONTRACTS.md:269)). The gate additionally leaves missing episode facts undefined and gives overlapping conditions for missing red flags and active response. **Required:** define durable idempotent interrupt delivery, bounded cancellation execution, and transactional state-version revalidation before displaying or applying model output. Make gate precedence explicit, with active response first and missing facts producing a defined safe outcome. Test commit/delivery crashes and both gate-versus-signal races.

12. **[major] Sections 3.2 and 8: answer classification does not define semantic validation or version selection.** A positive red flag is recognized only when `answer.value` matches a configured choice; everything else falls through to no signal ([E11:138](docs/tdd/E11.md:138)). Yet `AnswerCreate` permits a present answer with no `value`, while accepted answers carry `questionnaire_version` ([requests.schema.json:508](api/schemas/requests.schema.json:508), [answer.schema.json:14](api/schemas/answer.schema.json:14)). E11 names an active-release reader without stating how it honors that version. **Required:** define the boundary that validates choice ID, presence and value consistency, and classification against the applicable immutable configuration. Specify handling of unavailable versions and offline release mismatches without losing the original answer. Add parser properties and tests for missing values, contradictory fields and changed flow mappings.

13. **[major] Sections 5.1 and 9: the SQL backup does not prevent silent disposition.** The claimed backup is the cycle trigger ([E11:544](docs/tdd/E11.md:544)), but its checks only prohibit selected state changes and enforce revision increments. Executing the supplied DDL in an in-memory SQLite database allowed `active_response` to become `disposition_recorded` with an empty rationale, actor `{}`, and zero signal records. This contradicts the required authorized disposition and rationale ([CONTRACTS.md:119](CONTRACTS.md:119)). **Required:** redesign the independent safeguard, including valid disposition evidence, nonempty rationale and required atomic history. Extend T-E11-060 to attempt unauthorized closure, not just rank decreases. State precisely which failures the database safeguard can detect.

14. **[major] Sections 3.1, 4.2 and 11: resource bounds are asserted but not defined.** `UrgentCycle` contains its entire signal tuple, repository reads return unrestricted sequences, and a 24-hour expiry is presented as a table bound ([E11:103](docs/tdd/E11.md:103), [E11:315](docs/tdd/E11.md:315), [E11:580](docs/tdd/E11.md:580)). An active cycle or a burst of unresolved links can grow without limit. The charter requires bounded queues and timeouts on external calls ([BUILD-CHARTER.md:90](docs/BUILD-CHARTER.md:90)). **Required:** define bounded query batches, summary state separate from paginated history, queue admission and overflow behavior, SQLite lock deadlines, and memory budgets. Put runtime limits in named configuration fields with provenance. Preserve accepted history instead of silently evicting it.

15. **[major] Sections 5, 9, 10 and 12: storage and clock failures lack defined outcomes and tests.** The test plan covers duplicate answers but not crash or power loss during the combined answer, urgency, audit and outbox transaction; disk exhaustion; clock corrections; or corrupt configuration activation. The package requires that these records commit together ([CONTRACTS.md:1108](CONTRACTS.md:1108)) and that recovery faults have visible outcomes ([PRD.md:621](PRD.md:621)). **Required:** specify E11’s behavior at each failure point, including accepted versus unsaved status, retry recovery, historical versus current signal time, and retention of the last valid configuration. Define typed storage and boundary errors and their API mapping. Add fault tests against the real E01 transaction seam, with named ownership for any delegated checks.

16. **[major] Sections 4.3, 7 and 14: urgency can change without reaching an already open screen.** The design permits refresh only on navigation and claims help events cover everything safety relevant ([E11:364](docs/tdd/E11.md:364)). Uncertain answers, model review requests and person warnings can change urgency without opening or changing a help session. The package’s existing event list indeed has no episode event ([CONTRACTS.md:985](CONTRACTS.md:985)); this cannot be solved by assuming one exists. **Required:** make the requested notification contract an integration prerequisite or define bounded refresh through existing endpoints. Specify the UI owner, authorized recipients, stale/offline state, signal age and disposition attribution. Test a second client already displaying the episode when urgency changes.

17. **[major] Sections 1, 12 and 15: several traceability claims do not test the named acceptance criteria.** T-E11-007 tests a normal reading after a symptom, while V03 is “Concerning first measurement” with no repeat prerequisite ([VALIDATION.md:23](VALIDATION.md:23)). D25 is claimed as preventing model closure, but actually requires pinned-flow or kit citations and rejection of a medicine-naming turn ([VALIDATION.md:180](VALIDATION.md:180)). T-E11-012 tests origin rejection rather than V40’s explicit simulation mode and absence of real external messages. **Required:** correct the requirement/scenario/assertion matrix, distinguish E11’s contribution from the complete acceptance test, and name the owning integration test for each remainder. Add property tests for the red-flag parser and pathway/request rule engines. Ensure the build gates execute the actual mapped tests, including the claimed D06 and D30 contributions.
