VERDICT: CHANGES REQUESTED

1. **[blocker] Section 5.4: Configuration validation can be bypassed.** [E01:572](docs/tdd/E01.md:572) makes every missing loader check a warning in SIM and REPLAY. CONTRACTS.md:527 requires all checks; only the specific failure described by check 15 gets the exception at line 543. Activation also reruns checks only when their fingerprint changes, with no specified guard for `example: true` kits entering LIVE mode. Startup retains a release even when current validation rejects it at E01:577. **Required:** reject missing checks in every mode, limit the exception to executed check-15 findings, check current mission restrictions transactionally at activation, and define a safe recovery path for startup validation errors. Test each case.

2. **[blocker] Section 4.2: Evaluator isolation swallows storage failures.** [E01:270](docs/tdd/E01.md:270) says every non-domain exception preserves the input and schedules evaluation. That includes the storage exceptions mapped at E01:498. SYSTEM.md:973 explicitly requires storage faults to roll back the entire command. The helper also does not specify where the required durable `evaluation_pending` marker lives. **Required:** propagate storage failures to the outer transaction, define persistent pending state and its recovery/clearing protocol, and test storage failure inside an evaluator separately from an ordinary evaluator failure.

3. **[blocker] Sections 1 and 5.5: The migration policy prevents the promised software rollback.** [E01:34](docs/tdd/E01.md:34) promises that previous software reads the expanded database, but E01:587 refuses every migration absent from that software. After any upgrade migration, rolling back therefore enters safe mode. This contradicts DEPLOYMENT.md:473 and its pointer-only rollback at line 475. Restoring the pre-migration backup can also discard records accepted since upgrade. **Required:** define an explicit schema compatibility policy that permits supported additive migrations while rejecting incompatible schemas. Test upgrade, acceptance of new records, and rollback to the previous executable without losing those records.

4. **[blocker] Sections 4.1, 4.2 and 5.2: Generic idempotency stores private journal content.** [E01:242](docs/tdd/E01.md:242) sends every command through a runner that stores exact response bytes; `platform_idempotency` contains those bytes and an ordinary body hash at line 512. There is no journal exception or replay renderer. This cannot implement the keyed fingerprint and sealed-store protocol required by coordinator decision D4 and E03:373. **Required:** explicitly support D4, keeping journal plaintext and unkeyed text fingerprints out of hub storage, logs and caches. Specify authorized response reconstruction and crash recovery, and test retries before and after cache expiry.

5. **[blocker] Sections 3.4 and 4.3: Observation acceptance omits essential validation.** The prescribed algorithm at [E01:407](docs/tdd/E01.md:407) checks commensurability but never checks the code’s `accepted_units` or `methods`, despite declaring both at line 672. It accepts an in-range value without a quality claim, without limiting that path to manual acquisitions. It also never validates that `episode_id` belongs to the same patient, mission and origin. Thus an HTTP caller can claim a device or camera method without its quality gate, or attach a reading to another patient’s episode. **Required:** define and enforce those checks before insertion, distinguish trusted producer claims from manual input, and add negative tests for each bypass. This is required by CONTRACTS.md:7, :11, :241 and :244.

6. **[blocker] Section 6.1: Observation authorization loses consent restrictions.** [E01:637](docs/tdd/E01.md:637) returns the full observation to ground after a boolean consent check. Consent includes allowed fields/actions under CONTRACTS.md:21, and E02:359 provides field restrictions through `ConsentQueries.fields`. E01 also invents subject binding at lines 644 to 646, including an officer bypass, instead of using the E02 binding contract at E02:405. **Required:** integrate E02’s `AccessPolicy`, `AccessAudit` and `SubjectBinding`. Require authorization for every returned field, or deny when the fixed response cannot honor a restricted grant. Test revoked and partial grants, task expiration and cross-person recording.

7. **[blocker] Section 5.3: Clinical events fail open when their audience is omitted.** [E01:544](docs/tdd/E01.md:544) checks an audience only when one is supplied. A P2 event with crew scope and null audience therefore reaches every crew session through step 1. Denying an unknown rule does not cover an absent rule. SYSTEM.md:864 and :872 require object-level authorization for clinical event delivery. **Required:** require a registered audience policy for every P2 event type and reject or withhold events lacking it. Add tests for omitted audience metadata, closed sessions and revoked access.

8. **[blocker] Sections 3.5 and 5.6: The stated logging safeguards permit private text.** [E01:604](docs/tdd/E01.md:604) allows all `Problem` fields into logs, while SYSTEM.md:290 maps the error message into `Problem.detail`. Separately, the audit regex at E01:214 accepts arbitrary sensitive words containing no spaces; it does not establish that metadata is safe. SYSTEM.md:879 permits IDs and codes only. **Required:** define a sanitized log representation preserving the required Problem format without private detail, and allowlist audit metadata fields and their value types. Extend canary tests to error messages, `Problem.detail`, and sensitive strings that pass the current regex.

9. **[major] Section 5.3: Filtered event pages cannot advance their cursor.** [E01:537](docs/tdd/E01.md:537) reads a bounded raw page before filtering, but line 552 sets `next_cursor` to the last delivered event. If a full page belongs to other people or excluded types, nothing is delivered and the next request reads that same page forever. Later authorized events become unreachable. **Required:** distinguish the scanned cursor from the delivered event ID, define empty-page and `has_more` behavior, and bound scanning per request. Test multiple completely filtered pages followed by an authorized event, including restart and resume.

10. **[blocker] Sections 3.5 and 5.3: The operator skip command can discard required subscriber effects.** [E01:559](docs/tdd/E01.md:559) promises subscribers never skip, then provides `events skip <subscriber> <seq>` without restricting subscribers or repairing their missed effects. Advancing past an answer or measurement event can permanently omit a safety evaluation. An audit entry does not replace that evaluation. **Required:** remove unrestricted skipping from critical subscribers, or specify a recovery protocol that reconstructs the required effects before advancing. Test poison-event recovery without losing clinical facts or silently restoring healthy status.
