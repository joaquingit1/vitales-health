1. **[blocker] Sections 4 and 6: The universal authentication pipeline prevents public health checks and sign-in. Introduced by the revision.**

   [E01:392](docs/tdd/E01.md:392) requires an “authenticated SessionContext” **for every request**; section 4 likewise authenticates before command processing. However, [OpenAPI:65](docs/product/api/openapi.yaml:65) and [OpenAPI:107](docs/product/api/openapi.yaml:107) explicitly make `getHealth` and `createSession` unauthenticated with `security: []`. Requiring an existing session to create one makes initial sign-in impossible. The previous design explicitly described health as requiring “no session.”

   **Required change:** Generate authentication handling from effective operation security, explicitly preserving these public routes. Credential validation belongs inside `createSession`; protected operations still require session and role checks. Add assembled-middleware tests for health and successful sign-in without a bearer token, plus rejection of unauthenticated protected requests.

2. **[blocker] Sections 2, 4 and 12: The records-owned answer event has disappeared from the acceptance path. Introduced by the revision.**

   [E01:253](docs/tdd/E01.md:253) describes only an E03-owned answer transaction and says E03 publishes its internal event. The revised TDD contains no `AnswerAccepted` declaration or requirement that E01’s append operation publishes it. The previous design explicitly supplied both.

   This is a safety dependency: [SYSTEM:96](docs/SYSTEM.md:96) assigns `AnswerAccepted` to E01 records; [E04:77](docs/tdd/E04.md:77) requires its publication from `AnswerStore.append`; [E11:54](docs/tdd/E11.md:54) runs urgency evaluation inside that transaction. Following the revised application table leaves intake answers without a specified trigger for those evaluations.

   **Required change:** Restore E01’s publication obligation for every applicable answer producer, including E04. File the exact shared payload agreement in R-E01-17, distinguish it from E03 completion events, and require dispatch within the caller’s UOW using SYSTEM’s evaluation isolation. Add integration tests proving an E04 answer reaches urgency/rule consumers, computation failure leaves durable pending evaluation, storage failure aborts, and retries do not duplicate effects.

3. **[major] Section 2: The required text-validation application port was removed without a replacement or request. Introduced by the revision.**

   [E01:169](docs/tdd/E01.md:169) says E26 uses only canonical shared ports and has “no additional module-specific port.” Yet [E26:64](docs/tdd/E26.md:64) requires E01’s `TextRulesPort`, and [E12:331](docs/tdd/E12.md:331) requires the E01 application-port contract for amount detection. Owning `config/domain/text_rules.py` does not provide a legal cross-module interface. Neither the revised inventory nor E01’s requests resolves these calls.

   **Required change:** Restore this seam to the inventory and file agreement on exact methods, inputs, results and release binding with its consumers. Add provider/consumer contract tests and an import-boundary check. Reconcile the current caller signatures rather than simply restoring an incompatible old signature.

4. **[major] Section 2 and R-E01-17: Record-query consolidation still omits required capabilities. Present before the revision and still incomplete.**

   [R-E01-17:185](docs/requests/E01.md:185) covers facts, answer paging and a limited accepted-observation query. It does not cover:

   - E26’s bounded time-window observation reads, [E26:400](docs/tdd/E26.md:400).
   - E28’s batched observation references with acquisition and guided-check provenance, [E28:348](docs/tdd/E28.md:348).
   - E30’s independent-reference lookup over a window with excluded acquisition methods, [E30:480](docs/tdd/E30.md:480).

   These are capabilities, not aliases for the existing request’s signatures. E26 is also absent from E01’s record-consumer row.

   **Required change:** Extend the inventory and R-E01-17 to cover these consumers and their required projections. Specify bounded queries, partition and authorization context, time semantics and provenance. Require T-E01-02 to exercise the actual consumers against the agreed provider.

5. **[major] Section 15: The coverage command does not enforce the stated coverage rule. Introduced by the revision; prior finding 19 remains partly resolved.**

   [E01:732](docs/tdd/E01.md:732) requires at least 95% branch coverage for **each owned domain/application module**, without adapter dilution. [E01:746](docs/tdd/E01.md:746) instead measures all `crew_health` with one aggregate threshold while selecting E01 tests. That can include other epics and adapters, and an aggregate pass does not prove each required module passes. The declared validator subcommands do not supply the missing per-module check.

   **Required change:** Define the exact owned domain/application coverage set and an executable gate that checks each required module independently from the generated coverage report. Make unrelated modules and adapters unable to improve or depress that result.

6. **[major] Section 15: No declared command validates the complete hub configuration and example corpus. Introduced by the revision; prior finding 19 remains partly resolved.**

   [E01:727](docs/tdd/E01.md:727) defines interface, generation, safety, mutation and trace checks. Its generation check compares regenerated hashes. The separate command at line 739 runs [validate_contracts.py:1](scripts/validate_contracts.py:1), which validates the **pharmacy engine**.

   [SYSTEM:1656](docs/SYSTEM.md:1656) assigns hub configuration validation to `validate_hub.py`, and [CONTRACTS:527](docs/product/CONTRACTS.md:527) requires all sixteen checks against the research files and example documents. Tests of check behavior do not explicitly establish that the complete supplied corpus is validated.

   **Required change:** Define and invoke a hub-validation command that enumerates the required corpus, validates schemas/examples and executes every required cross-check. Specify effective-overlay handling and explicitly reported superseded base assertions. Missing contributors or an invalid required artifact must fail the gate.
