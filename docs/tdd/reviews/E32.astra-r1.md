1. **[blocker] Sections 2, 3.1, 4.3 and 6.2: configuration versions are not preserved across supply commands.** `record_step_uses` receives no release handle or configuration pins, while DD7 explicitly ignores a mismatched `Config-Release` (`docs/tdd/E32.md:102`, `:313`, `:451`). The package says an open plan run “pins onboard-plans, skills-catalog, role-rules, kit-map and ui-copy ... for its life” (`CONTRACTS.md:1269`) and configuration-dependent mutations under another release return `409 CONFIG_VERSION_MISMATCH` (`:214`). **Required:** pass the run’s pinned definitions into the ledger, define how they reference current physical stock, and enforce the release-header rule until an exception is approved. Test an open run across changes to its supply, unit and `per_use`, including a concurrent activation.

2. **[blocker] Sections 3.3 and 8.3: configuration activation can create negative or reinterpreted stock.** Balance is active packed quantity minus all historical uses (`docs/tdd/E32.md:155`), but none of S-L1 through S-L6 checks existing ledger state. Reducing packed quantity below consumption produces a negative response, forbidden by `api/schemas/supply-stock.schema.json:43` through `:47`. Changing a supply’s unit reinterprets every historical use. **Required:** specify atomic activation checks against durable balances, unit stability and removal/reintroduction of supply IDs. Define cumulative packed quantity and restocking semantics explicitly. Reject incompatible releases while retaining the last good release; test these transitions.

3. **[blocker] Sections 3.3, 4.1, 5.1 and 10.1: provenance labels do not isolate operational state.** Supply totals filter only by supply and environment, although rows retain `origin_mode`; the table has no mission identifier. The UI labels the result using the current mission mode (`docs/tdd/E32.md:155`, `:375`, `:501`). SIM consumption can therefore affect a subsequent LIVE balance without appearing as SIM. Medicines similarly specify SIM inheritance from sensor series, but not from weight, assays, inspections or administration history. The package states, “No simulated patient answer or result enters LIVE mode” (`CONTRACTS.md:414`). **Required:** define enforced mission/profile isolation and origin compatibility for every input and ledger query. Test mode changes, mixed-origin inputs and reuse of identifiers across missions.

4. **[major] Sections 2, 4.5 and 12: E24 and E32 specify incompatible warning integration.** E32 offers `SupplyCoverFacts` and publishes post-commit `supply.used` (`docs/tdd/E32.md:80`, `:253`). E32’s fact type lacks those evidence fields. **Required:** agree one producer-owned interface, transaction boundary, evidence payload and recovery mechanism with E24. Record the agreement in section 14 and test actual registration, duplicate delivery, restart recovery and warning creation. An unspecified fake cannot establish E32-03 acceptance.

5. **[major] Sections 4.3, 6.3 and 14: the combined what-if cannot evaluate added instruments.** R-E32-02’s `PlanAvailability.evaluate` receives stock and extra holders, but no hypothetical instrument kit (`docs/tdd/E32.md:790`). Test a plan that becomes runnable only when an instrument, supply and skill are added together, plus concurrent real stock and release changes.

Applying that rule to the package examples removes `dressings`, which remains packed and displayed in `api/examples/supplies/cover-lunar.json:96` through `:113`. Treat reference completeness as a minimum inclusion check, not an exclusion rule.

The package says every number must come from configuration or state and directs modules to request missing configuration rather than put it in code (`CONTRACTS.md:439`, `:1113`). **Required:** obtain the quantity from approved configuration or explicit user input. 8. **[major] Sections 1, 7, 12 and 15: E32-05 can be declared complete without its required behavior.** Interim behavior hides trained-hand counts from ordinary crew and omits plan summaries and ground-purpose text (`docs/tdd/E32.md:798` through `:810`). 9. **[major] Section 7: freshness compares incompatible values and lacks race handling.** An `as_of` timestamp cannot be “older than the last `supply.used` seq” (`docs/tdd/E32.md:500`). The package defines `seq` as a monotonically increasing integer and requires reload after `CURSOR_EXPIRED` (`CONTRACTS.md:981`). **Required:** define snapshot invalidation using event cursors or a client request-generation mechanism, including reconnect, expired cursors, events arriving during a fetch and out-of-order responses. 10. **[blocker] Sections 3.4, 4.4 and 12: confirmation permits a different lot without recomputing the dose.** `ConfirmDose` accepts the lot actually used, and E32-T-58 checks only that this lot is decremented (`docs/tdd/E32.md:352`, `:722`). Define one atomic confirmation transaction that rechecks lot/product identity, stock, expiry, assessment validity, patient context and supersession. Test two different proposals confirmed concurrently for the same ingredient, not only duplicate confirmation of one proposal.

11. **[blocker] Sections 3.4, 3.5, 4.4 and 9: authoritative lot exclusions can be bypassed by missing or delayed assessments.** Selection excludes `do_not_use` and expired lots but never checks the source lot’s `active`, `recalled` or `consumed` status (`docs/tdd/E32.md:204`). The engine assesses only active lots (`pharmacy/pipeline.py:1734` through `:1742`), so a recalled lot can have no assessment and reach the labeled-amount fallback. An adverse inspection merely schedules background work, leaving the previous assessment usable. **Required:** enforce current lot status and adverse inspection holds synchronously, independently of assessment freshness or worker success. Never remove a known exclusion when an estimate expires. Test recall, inspection, expiry crossing, worker failure and confirmation races.

12. **[blocker] Sections 3.4 and 3.5: final deliverable amounts are not checked against every cumulative limit.** Period and cumulative checks precede rounding and potency compensation; the adjustment inequalities include only per-administration and catastrophic limits (`docs/tdd/E32.md:201` through `:228`). Specify the combination-product objective and refusal rule. Add boundary/property tests where rounding or compensation passes the single-dose limit but exceeds a remaining period allowance.

13. **[blocker] Sections 3.4, 4.4, 10.2 and 12: allergy override behavior contradicts itself and lacks an authority boundary.** Same-ingredient allergy creates a terminal refusal (`docs/tdd/E32.md:193` through `:197`), but E32-T-62 expects an override (`:726`). The cited medicines brief requires “the medical officer’s override with a reason” (`crew-health-medications-2026-11-14/DESIGN-BRIEF.md:14`). **Required:** distinguish non-overridable refusals from overridable alerts, specify the override transition and actor eligibility separately from ordinary confirmation, and test unauthorized overrides. Define how a refusal becomes a newly authorized proposal without mutating the original.
