VERDICT: CHANGES REQUESTED

1. **[blocker] Sections 2, 3.1, 4.2 and 4.3: the E25 integration cannot be implemented consistently.** E03 consumes `DailyCheckQuestionSource.added_questions` and `RoutineTodayPort`, while E25 provides `DailyCheckAdditionsPort.for_check(uow, person_id, mission_day, daily_check_id)` and `RoutineQueries`. E25 also consumes `added_question_ids` in both lifecycle events, which E03 omits. E03 reduces repeat scheduling to a nullable integer and then a set of question IDs, losing the individual repeat occurrences. The package explicitly defines `"repeat_after_minutes": {"type": "array"}`. Evidence: [E03:87](docs/tdd/E03.md:87), [E25:581](docs/tdd/E25.md:581), [routine schema:490](docs/product/api/schemas/config-routine-rules.schema.json:490). **Required change:** agree one interface and event payload with E25, retain occurrence identity and repeat timing, and specify additions received after start and after submission. Test both, including warning clearance and restart.

2. **[blocker] Sections 4 and 5.2: journal durability contradicts the promised transaction boundary.** Section 4 promises that every command commits its state, audit and events together. `JournalStore.append` has no unit of work, writes a separate database, and nevertheless requires an E01 audit entry. No recovery protocol connects those writes. The package requires: “One command is one transaction: the state change, the audit event and the outbox entry commit together.” Evidence: [E03:246](docs/tdd/E03.md:246), [E03:405](docs/tdd/E03.md:405), [CONTRACTS:1108](docs/product/CONTRACTS.md:1108). Attaching both files would not establish atomic crash recovery under WAL. [SQLite documentation](https://www.sqlite.org/lang_attach.html). **Required change:** agree an explicit durable journal transaction and audit protocol with E01/E02, including its acceptance point, synchronization settings, recovery and typed failures. Inject power loss and disk exhaustion between every durable step.

3. **[blocker] Sections 4.1, 4.5 and 5.2: command replay is not fully specified.** Submit commits before obtaining the `StreakView` that supposedly becomes its stored response. A crash there can leave a submitted check without the original response. Lazy abandonment and revision checks also appear before replay lookup, potentially rejecting an already accepted command. The journal table has no request fingerprint to distinguish the same key with different text. Section 4.1 additionally permits a second start “without a key,” contradicting section 6. The package says: “The same key with the same body returns the first result; with a different body, `409 DUPLICATE_COMMAND`.” [CONTRACTS:210](docs/product/CONTRACTS.md:210). **Required change:** specify authorization, replay lookup, validation and commit ordering; durably bind the request fingerprint and original response to acceptance; require the header consistently. Test crash before response creation, midnight retries, changed bodies and stale `If-Match` on an accepted retry.

4. **[major] Sections 2, 4.1 and 14: faithfully implementing the 24-hour key expiry leaves an unsafe upstream requirement unresolved.** A journal or reaction-test retry after expiry can create a second clinical record. There is no durable logical command identity independent of the response cache. Evidence: [E03:73](docs/tdd/E03.md:73), [CONTRACTS:210](docs/product/CONTRACTS.md:210), [audit finding 9](crew-health-build-2026-11-14/audit/AUDIT-astra.md:61). **Required change:** request permanent logical identities for accepted clinical commands, with bounded HTTP response caching treated separately. Specify replay after several weeks, restart and synchronization, preserving original actor, time and configuration. Add duplicate and changed-payload tests beyond 24 hours.

5. **[major] Sections 3.2, 4.3 and 5.3: clock correction can permanently prevent today's check.** A forward clock jump abandons a check. A correction back to that day then encounters the same unique row, which cannot leave `abandoned`. Replanning the timer does not resolve this. The stored check also lacks a mission-clock version. Finally, abandonment performed before raising `INVALID_TRANSITION` could itself roll back under the stated unit of work. Evidence: [E03:170](docs/tdd/E03.md:170), [E03:397](docs/tdd/E03.md:397). The package requires clock corrections to be recorded and gives corrections explicit effective ranges. [CONTRACTS:9](docs/product/CONTRACTS.md:9), [CONTRACTS:389](docs/product/CONTRACTS.md:389). **Required change:** define durable clock lineage, correction/reassignment semantics, abandonment commit behavior and handling of future or delayed answer timestamps. Test forward and backward jumps across a boundary without losing answers or making the corrected day unusable.

6. **[blocker] Sections 4.3, 7.6, 8 and 11: questionnaire pinning cannot survive configuration activation.** E03 promises that an open check retains its questionnaire version, but `DailyCheck` exposes no questionnaire pin, the UI fetches the active questionnaire, and the cache retains only the current and previous versions. A second activation or a new client can therefore render different questions from those the server validates. The package says a configuration-dependent mutation under a different active release returns `CONFIG_VERSION_MISMATCH`; only specified workflows have exceptions. [CONTRACTS:214](docs/product/CONTRACTS.md:214). **Required change:** request the check's explicit configuration pins and a supported way to retrieve them; define activation and request-header semantics for open checks; retain referenced versions. Test activation between rendering and answering, two subsequent activations, reconnect from another client and rejection of corrupt releases.

7. **[major] Sections 3.2, 3.3 and 5.1: answer correction and concurrent editing lack a coherent lineage rule.** After submission, a required answer cannot be corrected. Before submission, two clients can append conflicting answers without an expected predecessor. `supersedes` is checked for person and check, but not question or current chain head. Ordering by `linked_at` is also ambiguous when timestamps tie or the clock moves. Evidence: [E03:175](docs/tdd/E03.md:175), [E03:255](docs/tdd/E03.md:255), [E03:398](docs/tdd/E03.md:398). The package requires immutable corrections and says a changed answer does not void completion. [CONTRACTS:13](docs/product/CONTRACTS.md:13), [CONTRACTS:400](docs/product/CONTRACTS.md:400). **Required change:** define append-only correction chains, deterministic ordering and conflict handling, including corrections after submission that leave participation unchanged. Request any missing API precondition and test simultaneous corrections.

8. **[major] Section 4.1: selecting the latest accepted sleep observation since yesterday can misrepresent which night was measured.** With no new band upload, yesterday morning's estimate qualifies and can be presented as “last night.” The port also does not require a band acquisition method, a completed sleep interval or exclusion of superseded observations. Evidence: [E03:264](docs/tdd/E03.md:264). The package requires preserving observation time and explicitly states that a late arrival does not become fresh; the PRD describes a proposed band estimate that the person reviews. [CONTRACTS:9](docs/product/CONTRACTS.md:9), [PRD:188](docs/product/PRD.md:188). **Required change:** define the eligible sleep interval, source, quality, lineage and selection policy through E08/E01, with configured policy where needed. Display the estimate's date and method. Test missing last-night data, delayed uploads, naps, corrected estimates and self-reported observations.

9. **[major] Sections 3.3 and 4.1: boundary validation is incomplete.** The confirmation-choice branch does not require the choice's presence or validate its unit. Duration conversion is attributed to `canonical_unit(code) -> str`, which cannot convert a quantity. `StartDailyCheck` returns an existing check before checking the requested origin. Evidence: [E03:189](docs/tdd/E03.md:189), [E03:264](docs/tdd/E03.md:264). Repository rules require unit-bearing quantities and rejection of non-finite input. [AGENTS:36](AGENTS.md:36). **Required change:** specify strict validators for every answer branch, an actual typed conversion port preserving original and canonical units, and origin validation on both new and existing starts. Add property tests covering inconsistent presence, booleans, numeric strings, non-finite values, incompatible units and mismatched-origin repeated starts.

10. **[major] Sections 7.6, 8 and 12: configuration can change the wrong behavior while the UI hardcodes a configured range.** The UI explicitly renders scales from 0 to 10 instead of `scale.min` and `scale.max`. Conversely, the required-question loader accepts any nonempty subset, allowing a release to omit sleep or mood or require an optional task. The package says: “Submission requires an accepted answer, in any presence state, to the symptom question, sleep and mood.” [CONTRACTS:123](docs/product/CONTRACTS.md:123). Evidence: [E03:545](docs/tdd/E03.md:545), [E03:646](docs/tdd/E03.md:646). **Required change:** render configured scale bounds and enforce the binding completion semantics independently of editable content. Revise T-E03-040 to demonstrate permitted configuration changes, and add rejection tests for missing core questions or optional tasks becoming mandatory.

11. **[blocker] Section 7.1: the selected SSE client does not implement the authentication and recovery contract.** Native `EventSource` does not provide custom request headers or expose response status and heartbeat comments as the design assumes. The package requires a bearer token and recovery from `410 CURSOR_EXPIRED`. Evidence: [E03:452](docs/tdd/E03.md:452), [CONTRACTS:209](docs/product/CONTRACTS.md:209), [EventSource standard](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-eventsource-interface). **Required change:** specify a compatible authenticated stream implementation, such as bounded Fetch streaming, or request an approved alternative authentication contract. Define parser limits, cursor restoration, duplicate suppression, heartbeat observation, cancellation and 401/410 handling. Test reconnect and session replacement without putting tokens in URLs.

12. **[blocker] Sections 7.4, 7.10 and 9.3: transport failure detection is not measurement freshness.** Values become stale only after a fetch failure or `EventSource` error. An established but stalled connection can remain apparently current, and an old measurement can remain old even while transport works. Neither the indicator contract nor the rendering policy supplies a complete expiry rule. The package requires “Zero stale or offline readings shown as current or safe.” [PRD:598](docs/product/PRD.md:598). **Required change:** distinguish transport liveness, measurement age and source availability; define server-derived freshness and a client watchdog, including tab resume. Stop measurement-driven animation when freshness is lost. Also resolve the UX requirement for default breathing at 14/min without a measurement by clearly separating decorative motion from measured physiology. Test silent stalls, stale sources on healthy connections, partial readings and resumed tablets.

13. **[blocker] Sections 2 and 6: optional projection failures can hide safety information on Today.** Today assembly calls participation, insight and assistant ports, but has no failure-containment policy. `TodayView` requires participation objects, so a participation failure can fail the entire response containing warnings and routine items. E22 already identifies this and requests nullable participation. Evidence: [E03:440](docs/tdd/E03.md:440), [E22:622](docs/tdd/E22.md:622). The charter requires safety functions to survive optional-component failure. [BUILD-CHARTER:25](docs/BUILD-CHARTER.md:25). **Required change:** adopt a compatible partial-view contract or independent safety loads, with explicit unavailable states and bounded calls. Test failing participation, baseline and assistant providers while warnings, routine misses, record entry and cached help remain usable.

14. **[blocker] Sections 3.3, 7.6 and 9.1: emergency entry is not explicitly independent of saving and authentication.** The concern branch waits for answer acceptance, while the help branch has no explicit local-first ordering or failure sequence. DE03-11 says the shell shows “sign in only” without a station credential. The package requires fixed first help screens “before authentication is complete” and without any network call. [PRD:548](docs/product/PRD.md:548), [CONTRACTS:1045](docs/product/CONTRACTS.md:1045). **Required change:** define the urgent-answer handoff and persistent help control independently of answer persistence, authentication and optional modules. Specify preauthentication cache initialization and preservation of unsaved input. Test an incapacitated crew member, absent station credentials, disk-full answer submission and an unreachable hub while opening the first help screen within 500 ms.

15. **[blocker] Sections 5.2, 7.1 and 10: privacy protection does not cover asynchronous session changes or every journal response path.** Resetting Pinia does not specify cancellation of in-flight reads, clearing component drafts or rejecting a late response from the previous person. Disabling body logging only on journal POST leaves GET responses and validation/error logging unspecified. E03's blanket prohibition on browser person data also conflicts with E26's persistent help-command outbox. Evidence: [E03:412](docs/tdd/E03.md:412), [E03:707](docs/tdd/E03.md:707), [E26:435](docs/tdd/E26.md:435). **Required change:** agree one E02/E26 storage and session-lifecycle policy. Bind requests and pending commands to their original actor, reject late responses after a session change, clear private UI state, and suppress journal content across success and error logging. Test delayed responses, account switching, browser back navigation, failed validation and pending help commands after sign-out.

16. **[major] Sections 7 and 10: the live crew-goal requirement does not provide the privacy it claims.** E03 faithfully exposes an immediately changing aggregate on a shared station. In a small crew, observing the total before and after one person's check can reveal their participation without a named breakdown. The package nevertheless promises: “No screen ... returns one person's completions ... to anyone but that person.” [CONTRACTS:408](docs/product/CONTRACTS.md:408). This is explicitly raised by [audit finding 5](crew-health-build-2026-11-14/audit/AUDIT-astra.md:29). **Required change:** file a package change defining honest visibility and consent rules, with opt-in participation and a considered publication cadence. Do not claim inference-free privacy for exact small-crew totals. Add a sequential-observation privacy test covering HTTP, SSE and station displays.

17. **[blocker] Sections 3.4, 7.7 and X-E03-6: a client can submit an incomplete or malformed reaction test as completed.** The design checks trial count but does not define elapsed-duration validation, timestamp ordering, duplicate indices, overlapping trials, response/release consistency or the evidence that a timeout actually elapsed. The request lacks an end timestamp or measured duration. Null combinations are ambiguous, and the median rule does not explicitly say whether `timeout_lapse` is included. Evidence: [E03:206](docs/tdd/E03.md:206), [E03:894](docs/tdd/E03.md:894). The acceptance criterion requires interrupted tests to be invalidated and excluded. [backlog:124](docs/product/backlog.json:124). **Required change:** specify the complete acquisition state machine and server validation, including feedback timing, end-of-test behavior, held keys, duplicate input events, interruption persistence and timeout classification. Add adversarial property tests and independently checked scoring vectors.

18. **[major] Sections 3.4, 7.7 and X-E03-7: the proposed PVT evidence does not validate interchangeable browser/device measurements.** X-E03-7 promotes the 355 ms threshold to sourced, but the cited study used particular hardware and explicitly cautions that the threshold may depend on hardware. It does not validate this browser implementation or switching between touch, pointer and keyboard. The raw data also lacks a defined timing-quality record and reproducible acquisition version. Evidence: [E03:904](docs/tdd/E03.md:904), [RT26 limitations](https://pmc.ncbi.nlm.nih.gov/articles/PMC3197786/). **Required change:** separate source provenance from implementation validation. Label the implementation experimental, define timing calibration/qualification and compatible comparison cohorts with E14, retain device/input/software/timing metadata, and refuse unsupported comparisons. Request correction of ROUTINE.md's unqualified claim that this implementation shows when sleep loss is affecting the person.

19. **[major] Sections 4.2, 6 and 7.11: the view assembly and measurement-card contract are insufficient to build the promised UI.** `IndicatorSummaryPort` does not specify how self-reported sleep, mood, energy and stress become comparable inputs, or how `extra`, `why`, source lineage and missing trend points are assembled. The reaction card requires one arc per response, but HowYouAreView supplies daily aggregates and no retrieval route for historical trials. The generic card also omits the five sourced guidance headings required for sleep, mood and reaction tests. Evidence: [E03:312](docs/tdd/E03.md:312), [UX-DESIGN:409](docs/product/UX-DESIGN.md:409), [UX-DESIGN:547](docs/product/UX-DESIGN.md:547). **Required change:** provide a field-by-field projection map, exact owner ports and contract requests for unavailable data. Define gap rendering without interpolation and assign the complete card content explicitly to E03 or an agreed owning epic.

20. **[major] Sections 3.2, 4 and 6: optional-part attachment has no implemented command or event path.** `attach_optional` exists only in the state table. There is no observation attachment port, consumed observation event or application use case, and the journal write is not tied to a check revision. The internal reaction reference also differs from the API's required `reaction_test_occurrence_id`. The package explicitly requires optional observation IDs, reaction occurrence ID, band confirmation and journal existence. [daily-check schema:109](docs/product/api/schemas/daily-check.schema.json:109). **Required change:** define each attachment path and its identity, origin, day, revision and retry rules. Specify how the UI refetches `missing_question_ids` and the check ETag after an answer, because the answer response is only an `Answer`. Test optional attachments after submission and concurrent clients without changing completion.

21. **[major] Sections 1 and 7: profile settings and the check's review step are missing product scope.** `ProfileView` is reduced to text size and OS motion preferences. It has no specified persistence, profile editing, unknown/declined history states or API request. E04 explicitly assigns allergies, medicines and prior conditions to E03. The daily-check flow also jumps to E22's completion component without specifying the required review of observations, quality, attention items and next steps. Evidence: [E03:457](docs/tdd/E03.md:457), [E04:66](docs/tdd/E04.md:66). The PRD requires both first-use profile/history handling and that final review. [PRD:182](docs/product/PRD.md:182), [PRD:194](docs/product/PRD.md:194). **Required change:** design these flows and request their missing contracts, or record an agreed ownership transfer with acceptance tests.

22. **[major] Sections 7.6, 10 and T-E03-053: marks are derived from object type while the contract requires object state.** The mitigation says “answer: ring,” and the test says “Answer gives ring.” That draws reported-symptom marks for absent, unknown and declined answers, and potentially for nonsymptom answers. The package says: “Symptom Answer with presence `present`” receives a hollow ring; “symptom answer absent, unknown or declined” receives “No mark; words only.” [CONTRACTS:313](docs/product/CONTRACTS.md:313). **Required change:** implement the complete object-and-state decision table, including accepted versus rejected observations and nonsymptom answers. Test every presence and quality state, shared regions, and the required “Symptom, not measured” wording.

23. **[major] Sections 7, 8 and X-E03-8: clinical-content notice, eligibility and provenance are not carried through to rendering.** E03 owns questionnaires and indicator configuration but does not include their required `notice` in its rendering rules. Proposed next steps are keyed only by generic view state, without indicator-specific applicability or approved evidence. The package requires every clinical text to carry its review label, and unsupported guidance to show a fixed unsupported state. [PRD:542](docs/product/PRD.md:542), [UX-DESIGN:561](docs/product/UX-DESIGN.md:561). **Required change:** specify notice rendering, evidence/review metadata and applicability for every guidance field. Use the shared eligibility policy requested by [audit finding 4](crew-health-build-2026-11-14/audit/AUDIT-astra.md:23), rather than treating a notice as authorization for LIVE guidance. Test missing, withdrawn and inapplicable evidence.

24. **[major] Sections 4 and 6: the error contract silently diverges from the package.** Missing question IDs are placed in problem `detail`, and all errors are described as RFC 9457. The package's closed `ErrorEnvelope` has no `detail`, and validation failures belong in `field_errors`. Its OpenAPI responses use that envelope. Evidence: [E03:256](docs/tdd/E03.md:256), [error schema:127](docs/product/api/schemas/error.schema.json:127). **Required change:** file the exact shared RFC 9457 migration request required by the charter conflict, with an explicit interim wire format. Name the module's typed errors and mappings, including storage exhaustion, corruption, missing encryption keys, missing pins and dependency failure. Preserve the required `current_state` and field-level errors without leaking private content.

25. **[major] Sections 5 and 11: bounds and resource protection remain placeholders.** There are no concrete HTTP deadlines, SQLite lock-wait limits, stream-buffer bounds, answer-history limits or view-size limits. `settings.checks.sweep_batch` and reconnect settings have no defined source or schema. There is no E03 memory budget, and independent fallback tests do not establish behavior under simultaneous model, camera, rendering and storage load. Evidence: [E03:417](docs/tdd/E03.md:417), [E03:714](docs/tdd/E03.md:714). The charter requires bounded queues and timeouts on every external call. [BUILD-CHARTER:90](docs/BUILD-CHARTER.md:90). **Required change:** define operational bounds, typed failure behavior, scheduling priorities and measured memory/latency gates. Add combined-load, database-lock, exhausted-storage and renderer-failure tests. Include workload and interruption-recovery evaluation required by audit findings 10 and 13.

26. **[major] Sections 9.1 and 14: the multi-hub interim contradicts the local uniqueness invariant.** E03 permits two separate checks for one person/day on different hubs, but the schema rejects both when merged through `UNIQUE(person_id, mission_id, mission_day)`. Counting participation once does not reconcile answers, journal ownership, configuration versions or competing corrections. Evidence: [E03:397](docs/tdd/E03.md:397), [E03:668](docs/tdd/E03.md:668), [audit findings 8 and 9](crew-health-build-2026-11-14/audit/AUDIT-astra.md:53). **Required change:** make T3 explicitly blocked pending an approved authority and reconciliation design, or specify that design now. Preserve both histories, node/location provenance, original times and privacy boundaries. Test a disconnected rover and habitat recording the same person's day and later exchanging records.

27. **[major] Section 12: several test references do not prove the assertions claimed.** T-E03-015 omits transit storm-watch questions and does not establish the station-with-no-overlay negative case required by V51. T-E03-057 proves region-set equality, not V49's assessment behavior or D04's band-anchor behavior. T-E03-054 checks source words but not D01's replay date and exposure disclaimer. T-E03-070 trusts route metadata, while E24 warning and E25 routine routes are omitted from the declared medical-surface assignments. Evidence: [E03:575](docs/tdd/E03.md:575), [E03:762](docs/tdd/E03.md:762), [VALIDATION:69](docs/product/VALIDATION.md:69), [VALIDATION:156](docs/product/VALIDATION.md:156). **Required change:** map each assertion to an actual test or explicit owning-epic test. Add parser/conversion properties, independently checked clinical golden cases and named fault-injection tests for the defects above. Assert forbidden participation on known medical route IDs independently of their metadata.

28. **[major] Sections 13 to 15: the handoff is not ready for parallel implementation.** SYSTEM.md, DEPLOYMENT.md and `docs/requests/E03.md` are absent. Essential responsibilities remain assumed, and E03-02/E03-03 are explicitly blocked. X-E03-6 uses an incomplete response shape, while required scoring parameters remain unset. The build plan starts scoring before resolving those inputs and does not include all required lint, mutation, condition-coverage and integration evidence. Evidence: [E03:851](docs/tdd/E03.md:851), [E03:934](docs/tdd/E03.md:934), [audit findings 14 to 17](crew-health-build-2026-11-14/audit/AUDIT-astra.md:97). **Required change:** publish complete requests and their dispositions, settle shared identity/transaction/event/configuration/ownership seams, and make acceptance dependencies explicit in the build order. Integrate an early durable record, authenticated reload, journal and completion path. Bind subsequent review and gate evidence to immutable source, configuration and dependency hashes.
